AI आर्किटेक्चर नियम: एनिमी AI के लिए कभी भी एक बड़ा while-true लूप न लिखें। FSM और बिहेवियर ट्री से निर्णय और एक्शन को अलग रखें।

इंजीनियरिंग और संज्ञानात्मक उपकरण

ब्रेन टाइप टेस्ट सिस्टम आर्किटेक्चर और समस्या समाधान शैली 2048 पहेली लॉजिक और डेटा पदानुक्रम प्रशिक्षण प्रतिक्रिया समय टेस्ट रीयल-टाइम मोटर स्पीड का परीक्षण तनाव परीक्षण डिप्लॉयमेंट और बग के दौरान मानसिक नियंत्रण

Roblox में स्मार्ट एनिमी बनाने के लिए एक स्पष्ट निर्णय प्रणाली आवश्यक है। एक ही स्क्रिप्ट में ढेर सारी if-else शर्तें लिखने से गेम लैग करता है और सर्वर स्लो हो जाता है।

प्रोफेशनल गेम्स फाइनाइट स्टेट मशीन (FSM) और बिहेवियर ट्री का संयोजन उपयोग करते हैं। इस गाइड में ब्लैकबोर्ड डेटा, विज़न रेकास्ट और AI LOD के बारे में विस्तार से बताया गया है।

1. FSM बनाम बिहेवियर ट्री (BT)

गेम के अनुसार सही आर्किटेक्चर चुनें:

  • FSM: गश्त, पीछा और हमले जैसी स्पष्ट अवस्थाओं के लिए उपयुक्त।
  • Behavior Trees: जटिल बॉस और रणनीतिक फैसलों के लिए सबसे अच्छा।
  • हाइब्रिड आर्किटेक्चर: FSM को बड़े स्तर पर और BT को सूक्ष्म स्तर पर उपयोग करना।

2. ब्लैकबोर्ड पैटर्न और विज़न रेकास्टिंग

बिना लैग के देखने की क्षमता देना:

  • ब्लैकबोर्ड: NPC की मेमोरी (टारगेट, पिछली स्थिति, स्वास्थ्य) का डेटा स्टोर।
  • विज़न कोन: 110 डिग्री का दृष्टि कोण और दीवार के पीछे देखने से रोकने के लिए रेकास्ट।
  • रेकास्ट बजटिंग: हर 0.2 से 0.4 सेकंड में चेक करना।

3. Production Implementation Architecture

ServerScriptService.NPCFramework.StateMachine
-- Modular Finite State Machine for Roblox NPC
local StateMachine = {}
StateMachine.__index = StateMachine

function StateMachine.new(npcInstance, states, initialState)
    local self = setmetatable({}, StateMachine)
    self.NPC = npcInstance
    self.States = states
    self.CurrentState = nil
    self.Blackboard = {
        Target = nil,
        LastSeenPos = nil,
        Health = 100,
        PatrolPoints = {}
    }
    
    self:ChangeState(initialState)
    return self
end

function StateMachine:ChangeState(newStateName)
    if self.CurrentState and self.States[self.CurrentState].Exit then
        self.States[self.CurrentState]:Exit(self.NPC, self.Blackboard)
    end
    
    self.CurrentState = newStateName
    if self.States[newStateName] and self.States[newStateName].Enter then
        self.States[newStateName]:Enter(self.NPC, self.Blackboard)
    end
end

function StateMachine:Update(dt)
    if self.CurrentState and self.States[self.CurrentState].Update then
        local nextState = self.States[self.CurrentState]:Update(self.NPC, self.Blackboard, dt)
        if nextState and nextState ~= self.CurrentState then
            self:ChangeState(nextState)
        end
    end
end

return StateMachine

4. बिहेवियर ट्री के नोड्स

प्राथमिकता तय करने के नियम:

  • सेलेक्टर (?): पहली सफल शाखा तक चलना (हमला -> पीछा -> गश्त)।
  • सीक्वेंस (&): सभी चरणों का पूरा होना जरूरी (पास जाना -> मारना)।

5. सर्वर ऑप्टिमाइज़ेशन और AI LOD

100+ दुश्मनों के साथ 60 FPS बनाए रखना:

  • AI LOD: पास होने पर तेज और दूर होने पर धीमा अपडेट करना।
  • ऑब्जेक्ट पूलिंग: बार-बार नए NPC बनाने के बजाय पुराने मॉडल्स का पुनः उपयोग।
