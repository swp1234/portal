Nada arruína a reputação e o faturamento de um jogo no Roblox mais rápido do que a perda de dados dos jogadores. Quando servidores reiniciam ou os jogadores trocam de servidor rapidamente, o uso de `SetAsync` sobrescreve inventários inteiros.

Em 2026, o desenvolvimento sério exige uma persistência de dados blindada. Este guia técnico detalha o Session Locking, por que o `UpdateAsync` é fundamental e como o ProfileService zera a perda de dados.

Regra de Ouro do Roblox: Nunca utilize SetAsync para dados de jogadores online. Sempre use UpdateAsync com Session Locking.

1. As Causas da Perda de Dados: Condições de Corrida

Como servidores distribuídos podem acidentalmente apagar dados:

  • Condição de Corrida Entre Servidores: Se um jogador sai do Servidor A e entra no Servidor B rapidamente, o B pode carregar dados antigos antes de o A salvar.
  • Erros de Rede sem pcall: Falhas HTTP 500 sem tratamento interrompem a execução do script e cancelam o salvamento.
  • Limites de Taxa Excedidos: Ultrapassar a cota de gravações por minuto faz com que os dados sejam descartados silenciosamente.

2. Mecânica do Session Locking com ProfileService

Garante que apenas um servidor ativo tenha permissão de gravação:

  • Posse Ativa da Sessão: O Servidor A grava seu JobId nos metadados para travar o perfil.
  • Proteção contra Duplicações: O Servidor B aguarda ou desconecta o jogador se o Servidor A ainda detiver a trava.
  • Salvamento Automático: O ProfileService salva os perfis a cada 30 segundos em segundo plano.

3. Migrações Seguras e Versionamento de Esquema

Como adicionar recursos sem reiniciar o progresso dos jogadores:

  • Template Padrão: Defina uma tabela imutável com todas as variáveis iniciais (Moedas, Gemas, Configurações).
  • Padrão Reconcile: Profile:Reconcile() insere novas chaves sem sobrescrever dados existentes.
  • Versionamento: Incremente DataVersion para rodar funções de migração estrutural.

4. Script de Produção: Implementação do ProfileService

Script de servidor robusto e testado para produção:

ServerScriptService.DataManager (ProfileService)
local Players = game:GetService("Players")
local ProfileService = require(script.ProfileService)

local ProfileTemplate = {
    Coins = 100,
    Gems = 0,
    Inventory = {},
    LogInTimes = 0,
}

local ProfileStore = ProfileService.GetProfileStore(
    "PlayerData_v1.0",
    ProfileTemplate
)

local Profiles = {}

local function OnPlayerAdded(player)
    local profile = ProfileStore:LoadProfileAsync("Player_" .. player.UserId)
    if profile ~= nil then
        profile:AddUserId(player.UserId)
        profile:Reconcile()
        profile:ListenToRelease(function()
            Profiles[player] = nil
            player:Kick("Sessão aberta em outro servidor. Por favor, reconecte.")
        end)
        if player:IsDescendantOf(Players) == true then
            Profiles[player] = profile
        else
            profile:Release()
        end
    else
        player:Kick("Não foi possível carregar seus dados salvos.")
    end
end

local function OnPlayerRemoving(player)
    local profile = Profiles[player]
    if profile ~= nil then
        profile:Release()
    end
end

Players.PlayerAdded:Connect(OnPlayerAdded)
Players.PlayerRemoving:Connect(OnPlayerRemoving)

Carrega com Session Lock, adiciona novos campos com Reconcile e libera o cadeado de forma segura ao desconectar.

5. Otimização e Tolerância a Falhas

Boas práticas para jogos comerciais:

  • Tolerância com BindToClose: game:BindToClose garante até 30 segundos para salvar todos os dados antes do encerramento do servidor.
  • Mock DataStore no Studio: Use ProfileStore.Mock para testar localmente sem consumir limites na nuvem.
  • Compressão de Dados: Serializa inventários grandes em strings binárias para ficar abaixo do limite de 4MB por chave.

Perguntas Frequentes (Roblox DataStores & ProfileService)

Por que SetAsync é arriscado?

SetAsync sobrescreve a nuvem sem verificar outros servidores. Se o jogador trocar de sala rápido, dados novos podem ser apagados por gravações atrasadas.

O que é Session Locking de forma simples?

É um cadeado digital: apenas o servidor onde o jogador está online tem autorização para salvar, evitando duplicações e perdas.

Qual é o limite de tamanho por chave no Roblox em 2026?

Até 4 MB (4.194.304 caracteres JSON) por chave, espaço de sobra para milhares de itens.

O ProfileService salva dados se o servidor fechar?

Sim. Ele se conecta automaticamente a game:BindToClose para salvar e destravar todos os perfis ativos antes do encerramento da instância.
