생존 공포 게임의 추적자, RPG 던전 보스, 전술 밀리터리 봇 등 몰입감 있는 NPC를 제작할 때 가장 큰 문제는 비구조화된 코드입니다. 단일 스크립트에 수백 줄의 if-else 분기를 작성하면 길찾기가 먹통이 되고 서버 프레임이 급락합니다.

상용 게임 개발에서는 거시적 상태를 관리하는 유한 상태 머신(FSM)과 유연한 하위 전술을 결정하는 행동 트리(Behavior Tree)를 결합하여 사용합니다. 본 가이드에서는 블랙보드 데이터 저장소, 시야각(FOV) 레이캐스트, 어그로 시스템, 서버 틱 LOD 분산 기법을 상세히 다룹니다.

1. 유한 상태 머신(FSM)과 행동 트리(Behavior Tree) 비교

게임 장르와 복잡도에 따른 아키텍처 선정 기준:

  • 유한 상태 머신(FSM): 대기(Idle), 순찰(Patrol), 경계(Investigate), 추격(Chase), 공격(Attack) 등 명확한 단계가 있는 몹에 이상적입니다. 각 상태의 진입(Enter), 갱신(Update), 퇴장(Exit) 주기가 분리됩니다.
  • 행동 트리(BT): 체력이나 상황에 따라 엄폐, 버프 시전, 무기 교체, 후퇴 등 복합 전술을 구사하는 보스 몬스터에 최적화되어 있습니다.
  • 하이브리드 구조: 거시적 상태 전환은 FSM으로 관리하고, 전투 상태 내부의 세부 의사결정은 행동 트리로 처리하는 것이 업계 표준입니다.

2. 공유 블랙보드(Blackboard)와 시야각 감각 인지

서버 성능 저하 없이 NPC에게 정밀한 지각 능력을 부여하는 방법:

  • 블랙보드 패턴: NPC의 기억 데이터(목표 플레이어, 마지막 목격 위치, 경계도, 탄약 수)를 중앙 테이블에 저장하여 상태 간 공유합니다.
  • 시야각(FOV)과 레이캐스팅: 내적(Dot Product) 연산으로 플레이어가 110도 전방 시야각 내에 있는지 확인한 후, 레이캐스트로 벽 뒤에 가려져 있는지 검증합니다.
  • 감각 틱 분산: 60 FPS 매 프레임마다 레이캐스트를 돌리지 말고, 0.2~0.4초 간격으로 NPC들을 그룹화하여 엇갈리게 틱을 수행합니다.

3. Production Implementation Architecture

ServerScriptService.NPCFramework.StateMachine
-- Modular Finite State Machine for Roblox NPC
local StateMachine = {}
StateMachine.__index = StateMachine

function StateMachine.new(npcInstance, states, initialState)
    local self = setmetatable({}, StateMachine)
    self.NPC = npcInstance
    self.States = states
    self.CurrentState = nil
    self.Blackboard = {
        Target = nil,
        LastSeenPos = nil,
        Health = 100,
        PatrolPoints = {}
    }

    self:ChangeState(initialState)
    return self
end

function StateMachine:ChangeState(newStateName)
    if self.CurrentState and self.States[self.CurrentState].Exit then
        self.States[self.CurrentState]:Exit(self.NPC, self.Blackboard)
    end

    self.CurrentState = newStateName
    if self.States[newStateName] and self.States[newStateName].Enter then
        self.States[newStateName]:Enter(self.NPC, self.Blackboard)
    end
end

function StateMachine:Update(dt)
    if self.CurrentState and self.States[self.CurrentState].Update then
        local nextState = self.States[self.CurrentState]:Update(self.NPC, self.Blackboard, dt)
        if nextState and nextState ~= self.CurrentState then
            self:ChangeState(nextState)
        end
    end
end

return StateMachine

4. 행동 트리 노드 메커니즘: 선택자, 시퀀스와 데코레이터

계층적 우선순위 판단 시스템 구성:

  • 선택자 노드 (Selector, ?): 자식 노드 중 하나라도 성공하면 즉시 성공을 반환합니다. (공격 시도 -> 사거리 부족 시 추격 시도 -> 타깃 상실 시 순찰 복귀)
  • 시퀀스 노드 (Sequence, &): 모든 자식 노드가 차례로 성공해야 완료됩니다. (목표 접근 -> 공격 모션 재생 -> 대미지 적용 연계)
  • 데코레이터 노드 (Decorator): 쿨다운 타이머, 조건 반전, 반복 실행 등 자식 노드의 반환값을 제어합니다.

5. 대규모 서버 스케일링: AI LOD와 오브젝트 풀링

100마리 이상의 몬스터가 동시 활동할 때 서버 60 FPS를 사수하는 비결:

  • AI LOD(Level of Detail): 플레이어 근처(100 Stud)는 10Hz로 지각하고, 원거리(250 Stud 이상)는 1Hz로 갱신하며, 500 Stud 밖은 물리 연산을 중지합니다.
  • 클라이언트 이동 보간: 서버는 굵직한 웨이포인트 경로만 계산하고, 부드러운 회전과 걷기 애니메이션은 클라이언트가 보간하게 맡깁니다.
  • 오브젝트 풀링(Object Pooling): 스폰 시마다 Instance.new와 Destroy를 반복하지 않고, 미리 생성된 NPC 풀에서 투명도와 CFrame만 변경해 재사용합니다.

Frequently Asked Questions

적 몬스터가 30마리만 넘어가면 왜 서버가 멈칫거리나요?

Heartbeat마다 모든 NPC의 레이캐스트와 경로 계산을 실행하기 때문입니다. AI LOD를 적용해 원거리 NPC의 연산 주기를 늘리고 프레임별로 분산 처리해야 합니다.

행동 트리가 상태 머신보다 우수한 점은 무엇인가요?

새로운 행동을 추가할 때 기존 상태들의 전이 화살표를 일일이 수정할 필요 없이, 트리에 노드 하나만 끼워 넣으면 되는 유연성과 모듈성입니다.

NPC가 벽 뒤의 플레이어를 투시하지 못하게 하려면?

NPC의 머리에서 플레이어의 몸통으로 레이캐스트를 쏘아, 벽이나 기둥에 가려지는지 RaycastResult로 검증해야 합니다.

클라이언트 스크립트에서 NPC 인공지능을 직접 돌려도 되나요?

대미지 판정이나 타깃 지정 등 핵심 로직은 반드시 서버가 제어해야 핵과 변조를 방지할 수 있습니다. 클라이언트는 시각적 애니메이션 보간만 담당해야 합니다.
