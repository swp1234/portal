로블록스 서바이벌, 공포, RPG 게임에서 적 NPC가 문틀에 끼이거나 울타리 앞에서 덜덜 떨며 벽을 뚫으려 하는 것만큼 유저 몰입을 깨뜨리는 것은 없습니다. 생동감 넘치는 반응형 NPC를 만들기 위해서는 로블록스의 3D 내비메시(Navmesh) 내비게이션 엔진을 정확히 이해해야 합니다.

로블록스 내장 `PathfindingService`는 물리 시뮬레이션 환경에 맞춰 최적화된 엔터프라이즈급 A* 경로 연산을 제공합니다. 본 엔지니어링 가이드에서는 에이전트 매개변수 설정, `PathfindingModifier` 비용 가중치, 재연산 백오프, 레이캐스트 시야각 최적화를 활용하여 고성능 상업용 AI를 구현하는 방법을 다룹니다.

NPC 내비게이션의 절대 원칙: 단순 Humanoid:MoveTo()에만 의존하지 마세요. 반드시 PathfindingService로 검증된 웨이포인트를 생성하고 레이캐스트 직접 시야각을 병행해야 끊김 현상을 방지할 수 있습니다.

1. 로블록스 경로 연산 원리: 3D 내비메시 복셀 그리드

엔진의 공간 연산 지오메트리를 이해하여 경로 탐색 실패를 방지하는 법:

  • 내비메시 복셀 그리드: 엔진은 3D 공간을 복셀 단위로 분할합니다. NPC의 AgentRadius나 AgentHeight가 문 통로보다 크면 Enum.PathStatus.NoPath를 반환합니다.
  • 에이전트 파라미터 테이블: 캐릭터 리그의 실제 크기에 맞춰 AgentRadius, AgentHeight, AgentCanJump, AgentCanClimb 값을 정밀하게 설정하세요.
  • 웨이포인트 공간 분할: 연산 결과는 3D 좌표와 액션 상태(걷기 vs 점프)를 담은 PathWaypoint 배열로 반환됩니다.

2. PathfindingModifier와 커스텀 재질 비용 가중치

NPC가 선호하거나 회피할 지형을 지능적으로 제어하기:

  • PathfindingModifier 오브젝트: BasePart 내부에 삽입하여 고유 라벨(예: "Lava", "Water", "Road", "Door")을 부여합니다.
  • 비용 가중치 딕셔너리: Costs = { Lava = math.huge, Road = 0.5 } 형태로 배율을 지정합니다. 위험 지역은 무한대 비용으로 우회시키고 도로는 낮은 비용으로 유도합니다.
  • PassThrough 플래그: 문이나 파괴 가능한 장애물에 PassThrough = true를 설정하면 닫혀 있어도 통과 가능한 경로로 인식합니다.

3. 버벅임 제거: 레이캐스팅과 직진 추적 최적화

기계적인 망설임과 지연 시간을 없애는 아키텍처 테크닉:

  • 직접 시야각(Line-of-Sight) 레이캐스트: 무거운 경로 연산을 매번 실행하기 전 플레이어 방향으로 레이를 쏴 장애물이 없으면 웨이포인트를 건너뛰고 직진합니다.
  • 웨이포인트 도달 판정 완화: 정확한 좌표에 멈출 때까지 기다리지 말고 3~4스터드 이내로 접근하면 다음 웨이포인트로 즉시 넘어가 유연한 보행을 유지하세요.
  • 연산 주기 조절(Throttling): 플레이어가 이전 목표점에서 8스터드 이상 이동했거나 0.3~0.5초 주기로만 경로를 재계산하세요.

4. 실전 프로덕션 Lua 스크립트: 스마트 추적 AI

레이캐스트 지름길과 멈춤 감지 타임아웃을 내장한 고성능 NPC 추적 스크립트:

ServerScriptService.SmartNPCChaser (길찾기 핸들러)
local PathfindingService = game:GetService("PathfindingService")
local Players = game:GetService("Players")

local npc = script.Parent
local humanoid = npc:WaitForChild("Humanoid")
local rootPart = npc:WaitForChild("HumanoidRootPart")

local path = PathfindingService:CreatePath({
    AgentRadius = 3,
    AgentHeight = 6,
    AgentCanJump = true,
    WaypointSpacing = 4,
    Costs = {
        Water = 20,
        DangerZone = math.huge
    }
})

local function HasLineOfSight(targetPart)
    local origin = rootPart.Position
    local direction = (targetPart.Position - origin)
    local params = RaycastParams.new()
    params.FilterDescendantsInstances = {npc, targetPart.Parent}
    params.FilterType = RaycastFilterType.Exclude
    local result = workspace:Raycast(origin, direction, params)
    return result == nil
end

local function FollowPath(targetPosition)
    local success, errorMessage = pcall(function()
        path:ComputeAsync(rootPart.Position, targetPosition)
    end)

    if success and path.Status == Enum.PathStatus.Success then
        local waypoints = path:GetWaypoints()
        for i, waypoint in ipairs(waypoints) do
            if waypoint.Action == Enum.PathWaypointAction.Jump then
                humanoid.Jump = true
            end
            humanoid:MoveTo(waypoint.Position)
            local reached = humanoid.MoveToFinished:Wait(1)
            if not reached then
                humanoid.Jump = true
                break
            end
        end
    end
end

핵심 아키텍처: 커스텀 에이전트 규격으로 경로를 계산하고, 도달 실패 시 점프 탈출을 시도하며, 수직 점프 액션을 정확히 동기화합니다.

5. 대규모 동시 NPC 시뮬레이션을 위한 성능 튜닝

서버 렉 없이 50개 이상의 NPC를 동시에 구동하는 최적화 비법:

  • 클라이언트 위치 보간: 서버는 물리 및 의사결정 경로만 계산하고, 부드러운 위치 렌더링은 클라이언트 트윈으로 분산 처리하세요.
  • AI 거리별 LOD(Level of Detail): 유저와 150스터드 이상 떨어진 NPC는 경로 갱신 주기를 1~2초로 대폭 늘리세요.
  • 연산 큐 분산: 프레임마다 연산 요청을 큐로 분산시켜 로블록스 엔진의 분당 500회 경로 연산 제한을 넘지 않도록 관리하세요.

무료 인지 & 두뇌 유형 테스트 시작하기

자주 묻는 질문 (로블록스 PathfindingService)

Path.Status가 Enum.PathStatus.NoPath를 반환하는 이유는 무엇인가요?

목표 지점이 고체 지오메트리 내부에 갇혀 있거나, 통로 폭이 AgentRadius/AgentHeight 설정보다 좁아서 통과할 수 없을 때 발생합니다.

NPC가 모서리에 자꾸 걸리는 문제를 어떻게 해결하나요?

AgentRadius를 시각적 메시 크기보다 약 20~30% 크게 설정하면 벽 모서리로부터 충분히 떨어진 안전 경로를 생성할 수 있습니다.

MoveTo와 PathfindingService의 성능 차이는 얼마나 큰가요?

MoveTo는 단순 직선 이동으로 연산 비용이 거의 없지만 장애물을 전혀 피하지 못합니다. PathfindingService는 A* 그래프 탐색을 수행하므로 연산 비용이 들지만 충돌 없는 최적 경로를 보장합니다.
