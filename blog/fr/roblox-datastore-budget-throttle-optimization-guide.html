Optimisation de Budget et Throttling Roblox DataStore : Cache, Files d'Attente et Sécurité

By DopaBrain Roblox Tech Architecture Team • Updated: September 2026 • Reading Time: 9 min
Règle d'Architecture : Ne traitez jamais Roblox DataStore comme une base de données temps réel. Mutez l'état dans la mémoire du serveur et sauvegardez de façon asynchrone avec verrouillage de session.

Dans les jeux Roblox à fort trafic, l'erreur "DataStore request was added to queue and dropped" provoque des pertes de données massives. Appeler GetAsync ou SetAsync à chaque action consomme rapidement le quota disponible.

Ce guide présente les architectures de production : suivi du budget de requêtes, mise en cache mémoire avec drapeaux de modification (dirty flags), retraits exponentiels sous UpdateAsync et session locking contre les failles de duplication.

1. Comprendre les Limites de Budget de Roblox DataStore

Roblox applique des quotas stricts calculés selon le nombre de joueurs présents :

  • Budget GetAsync : 60 + (nbJoueurs * 10) requêtes par minute sur l'ensemble des clés.
  • Budget SetAsync / UpdateAsync : 60 + (nbJoueurs * 10) requêtes d'écriture par minute.
  • Cooldown de 6 secondes : Écrire sur la même clé avant 6 secondes déclenche un rejet automatique.
  • Taille Maximale : 4 194 304 caractères (4 Mo) par clé.

2. Cache Mémoire et Sauvegarde Automatique Dirty Flag

Structure standard pour les jeux à grande échelle :

  • Chargement à l'entrée, vidage à la sortie : Une seule lecture DataStore lors de la connexion, conservée dans une table Lua en RAM.
  • Mutation en mémoire : Les gains d'or et d'expérience modifient uniquement la table Lua locale sans appel d'API.
  • Sauvegarde périodique sélective : Sauvegarde échelonnée toutes les 120-180 secondes uniquement pour les profils modifiés.
  • Clôture sécurisée : Utilisation de routines asynchrones parallèles reliées à game:BindToClose().

3. Production Implementation Architecture

ServerScriptService.DataStoreManager (Architecture de Réessai et Cache)
-- Safe DataStore Write with Exponential Backoff and Budget Check
local DataStoreService = game:GetService("DataStoreService")
local Players = game:GetService("Players")
local PlayerDataStore = DataStoreService:GetDataStore("PlayerCore_v1")

local MAX_RETRIES = 3
local BASE_DELAY = 1.5

local function safeUpdateAsync(key, transformFunc)
    local budget = DataStoreService:GetRequestBudgetForRequestType(Enum.DataStoreRequestType.UpdateAsync)
    if budget < 5 then
        warn("[DataStore] Throttling warning: Low budget for UpdateAsync (" .. tostring(budget) .. ")")
    end
    
    local success, result
    local attempts = 0
    
    repeat
        attempts = attempts + 1
        success, result = pcall(function()
            return PlayerDataStore:UpdateAsync(key, transformFunc)
        end)
        
        if not success then
            local delayTime = BASE_DELAY * (2 ^ (attempts - 1)) + math.random() * 0.5
            warn("[DataStore] Attempt " .. attempts .. " failed: " .. tostring(result) .. ". Retrying in " .. string.format("%.2f", delayTime) .. "s")
            task.wait(delayTime)
        end
    until success or attempts >= MAX_RETRIES
    
    return success, result
end

4. Verrouillage de Session et Protection contre la Duplication

Éliminer les corruptions lors des changements rapides de serveur :

  • Faille du Server Hop : Se connecter à un nouveau serveur avant la fin de l'écriture du précédent.
  • Session Lock : Enregistrement du JobId et de l'horodatage lors de l'activation de session.
  • Attente de libération : Le nouveau serveur patiente jusqu'au déblocage du verrou.
  • Adoption de ProfileService : Utilisation d'un framework standardisé éprouvé.

5. Migration de Schéma et Versionnage en Production

Garantir l'intégrité des profils lors des mises à jour du jeu :

  • En-tête de version : Champ _SchemaVersion pour orchestrer les migrations.
  • Réconciliation automatique : Fusion des clés par défaut dans les profils existants.
  • Nettoyage rétrocompatible : Transition douce avant la suppression des anciens champs.

Frequently Asked Questions

Pourquoi Roblox rejette-t-il les requêtes avec l'erreur de 6 secondes ?

Pour protéger ses infrastructures contre les écritures répétitives sur une même clé.

Quel est l'intérêt de ProfileService par rapport à l'API brute ?

Il intègre automatiquement le verrouillage de session, la gestion des fermetures serveur et la prévention des pertes de données.

Comment tester les limites DataStore dans Roblox Studio ?

En activant l'accès API dans les paramètres du jeu et en observant GetRequestBudgetForRequestType().

Comment éviter le dépassement des 30 secondes de BindToClose ?

En exécutant les sauvegardes par lots asynchrones parallèles via task.spawn au lieu de boucles séquentielles.
