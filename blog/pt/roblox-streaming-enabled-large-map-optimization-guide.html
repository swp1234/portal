Desenvolver grandes mapas abertos no Roblox impõe um desafio crítico: mais de 60% dos jogadores utilizam celulares com menos de 3GB de memória RAM. Replicar todo o cenário simultaneamente resulta em fechamentos forçados por falta de memória (OOM).

O recurso StreamingEnabled carrega e descarrega instâncias 3D dinamicamente com base na proximidade do personagem. Este guia detalha a configuração de ModelStreamingMode, RequestStreamAroundAsync e padrões de código resilientes no cliente.

1. Mecânica do StreamingEnabled: Raios e Liberação de Memória

Como a engine do Roblox gerencia o mapa dinamicamente:

  • StreamingTargetRadius: Raio máximo em studs onde os objetos são ativamente replicados e renderizados.
  • StreamingMinRadius: Raio interno primordial que nunca é descarregado sob nenhuma circunstância.
  • StreamOutBehavior: Descarrega trechos distantes de forma oportuna para preservar a memória do aparelho.
  • StreamingPauseMode: Pausa a física suavemente caso o jogador se mova mais rápido que o streaming.

2. ModelStreamingMode: Modos de Replicação para Modelos

Preservando a integridade estrutural de mecanismos e veículos:

  • Default: Partes filhas carregam separadamente, podendo quebrar visualmente o modelo.
  • Atomic: O modelo e todos os seus filhos carregam e descarregam como um bloco único e indivisível.
  • Persistent: Carregado ao entrar e mantido permanentemente na RAM (reservar para hubs centrais).
  • PersistentPerPlayer: Permite fixar modelos dinamicamente para jogadores específicos via scripts de servidor.

end

local function onObjectStreamedOut(instance)
    print("[Streaming] Interactive object unloaded: " .. instance.Name)
    -- Clean up any active local tweens, highlights, or sound emitters
end

CollectionService:GetInstanceAddedSignal(TAG_NAME):Connect(onObjectStreamedIn)
CollectionService:GetInstanceRemovedSignal(TAG_NAME):Connect(onObjectStreamedOut)

-- Initial sweep for parts already streamed in upon join

end

4. Teletransporte sem Queda no Vazio: RequestStreamAroundAsync

Eliminando o bug de cair no limbo ao mudar de posição:

  • O Perigo do Vazio: Mover o personagem antes de carregar o solo causa quedas sem fim.
  • Pré-carregamento de Terreno: Execute player:RequestStreamAroundAsync() antes do teletransporte.
  • Fixação Temporária: Mantenha o HumanoidRootPart com Anchored até o chão ser confirmado.

5. Gestão de Ativos: LOD e Atlas de Texturas

Otimização visual sem sobrecarregar a VRAM:

  • Mesh LOD: Ajuste RenderFidelity para Performance para reduzir polígonos à distância.
  • Atlas de Texturas: Agrupe texturas em imagens de 2048x2048 para reduzir Draw Calls.
  • Cenários Otimizados: Substitua montanhas distantes inacessíveis por modelos low-poly leves.

Frequently Asked Questions

Por que scripts antigos quebram com StreamingEnabled ativado?

Porque partes distantes não existem no cliente até que o jogador se aproxime. O acesso direto retorna erro nil.

Qual é a diferença entre Atomic e Persistent?

Atomic economiza RAM descarregando o modelo completo quando distante; Persistent mantém o modelo sempre em memória.

Como o StreamingEnabled evita quedas no mobile?

Mantendo na memória apenas algumas centenas de studs ao redor do jogador, estabilizando o uso de RAM abaixo de 800MB.

O servidor pode acessar partes descarregadas nos clientes?

Sim! O servidor sempre mantém o mapa completo em memória; o streaming afeta apenas a réplica para o cliente.
