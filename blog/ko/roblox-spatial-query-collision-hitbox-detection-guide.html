로블록스 Spatial Query & 히트박스 판정: OverlapParams, 레이캐스트 및 서버 안티핵 설계

개발자 인지 역량 도구

두뇌 유형 테스트 기하학 및 알고리즘 사고 반응속도 테스트 전투 타이밍 측정 스트레스 체크 넷코드 디버깅 피로도 2048 퍼즐 공간 행렬 논리

로블록스 액션 RPG, 대전 격투, 배틀로얄 게임에서 칼을 정면으로 맞췄는데도 허공을 가르거나, 수 미터 떨어진 곳에서 맞지 말아야 할 공격에 피격되는 "유령 히트"만큼 유저 경험을 해치는 요소는 없습니다.

고전적인 `BasePart.Touched` 이벤트는 물리 연산 스텝(60Hz)과 클라이언트 시뮬레이션 지연에 종속되어 있어 경쟁형 전투 게임에서 결코 신뢰할 수 없습니다. 상용 로블록스 대작들은 `WorldRoot`의 공간 쿼리 API(`GetPartsInPart`, `GetPartBoundsInBox`)와 `OverlapParams` 기반의 레이캐스트 히트박스를 표준으로 사용합니다.

히트박스 판정의 절대 원칙: 정밀 근접 공격에 Touched를 사용하지 마세요. 클라이언트 예측 쿼리와 서버 측 거리·시야각 무결성 검증을 병행해야 합니다.

1. Touched 이벤트가 실패하는 기술적 이유

물리 충돌 이벤트가 전투 판정에서 치명적인 결함을 드러내는 원인:

  • 물리 스텝 지연(터널링): 무기가 매우 빠르게 휘둘러지면 물리 시뮬레이션 프레임 사이를 지나쳐 충돌 이벤트가 누락되는 터널링 현상이 발생합니다.
  • 클라이언트 핵 취약성: 클라이언트가 자기 캐릭터의 물리 시뮬레이션을 소유하므로, 악의적 유저가 Touched를 원격 호출하거나 히트박스를 맵 전체로 부풀릴 수 있습니다.
  • 불규칙한 다중 호출: 칼을 한 번 휘둘렀을 때 찰나의 순간 동안 수십 번의 충돌 이벤트가 난타되어 서버 렉과 비정상 데미지를 유발합니다.

2. 최신 공간 쿼리(Spatial Query)와 OverlapParams

기하학적 교차 검사를 즉시 수행하는 로블록스의 강력한 공간 쿼리 함수군:

  • GetPartsInPart: 복잡한 메시나 파트의 3D 체적과 겹치는 파트들을 즉시 반환하여 회전 베기나 범위 공격(AoE)에 가장 적합합니다.
  • GetPartBoundsInBox / InRadius: 가벼운 육면체 및 구형 경계 검사로 폭발 반경이나 발사체 착탄 판정에 최적화되어 있습니다.
  • OverlapParams 설정: RaycastFilterType.Exclude로 시전자 자신을 제외하고, 충돌 그룹을 지정하여 불필요한 배경 오브젝트 검사를 사전에 차단합니다.

3. 레이캐스트 히트박스 vs 체적 공간 쿼리 비교

무기 특성에 따른 최적의 충돌 감지 아키텍처 선택:

  • DDA 레이캐스트 히트박스(검, 창): 칼날에 여러 개의 Attachment를 달고 프레임 간 궤적에 레이를 쏘아 궤적 전체를 빈틈없이 포착합니다.
  • 체적 공간 쿼리(해머, 둔기, 충격파): 궤적의 궤선보다 타격 순간의 묵직한 공간 부피가 중요한 공격에 유리합니다.
  • 클라이언트 선판정-서버 검증 하이브리드: 클라이언트는 이펙트와 피격 애니메이션을 즉시 출력하고, 서버는 거리와 시야각을 확인한 후 데미지를 인가합니다.

4. 실전 프로덕션 Lua 스크립트: 근접 공간 쿼리 핸들러

OverlapParams와 서버 거리 검증을 탑재한 상업용 전투 스크립트:

ServerScriptService.CombatManager (공간 쿼리 검증)
local Workspace = game:GetService("Workspace")

local function PerformMeleeCheck(attacker, weaponHitboxPart, maxTargets)
    local overlapParams = OverlapParams.new()
    overlapParams.FilterType = RaycastFilterType.Exclude
    overlapParams.FilterDescendantsInstances = {attacker.Character}
    overlapParams.MaxParts = 20
    overlapParams.CollisionGroup = "Default"

    local collidingParts = Workspace:GetPartsInPart(weaponHitboxPart, overlapParams)
    local hitHumanoids = {}
    local targetsDamaged = 0

    for _, part in ipairs(collidingParts) do
        local model = part:FindFirstAncestorOfClass("Model")
        if model and model ~= attacker.Character then
            local targetHumanoid = model:FindFirstChildOfClass("Humanoid")
            local targetRoot = model:FindFirstChild("HumanoidRootPart")

            if targetHumanoid and targetHumanoid.Health > 0 and not hitHumanoids[targetHumanoid] then
                hitHumanoids[targetHumanoid] = true

                -- Server validation: Validate distance from attacker
                local attackerRoot = attacker.Character:FindFirstChild("HumanoidRootPart")
                if attackerRoot and targetRoot then
                    local distance = (attackerRoot.Position - targetRoot.Position).Magnitude
                    if distance <= 18 then -- Maximum allowable reach threshold
                        targetHumanoid:TakeDamage(25)
                        targetsDamaged = targetsDamaged + 1
                        if targetsDamaged >= maxTargets then break end
                    end
                end
            end
        end
    end
end

주요 기능: 공격자 캐릭터 완벽 제외, 1타 다단히트 방지 필터링, 서버 측 18스터드 사거리 제한 검증을 통한 원거리 변조핵 차단.

5. 핑 차이 보정(Lag Compensation)과 안티치트 방벽

고핑 유저 간의 대전에서도 공정한 판정을 보장하는 원칙:

  • 과거 위치 히스토리 버퍼: 최근 150~200ms 동안의 피격자 위치를 버퍼에 기록하여 핑에 따른 오차를 서버에서 역추적 보정합니다.
  • 서버 쿨다운 엄격 통제: 애니메이션 완료 타이밍을 클라이언트에 맡기지 말고 서버 내부 타이머로 연속 공격 주기를 강제합니다.
  • 벽 관통 방지 레이캐스트: 공격자와 피격자 사이에 지형이나 벽이 가로막혀 있는지 레이캐스트로 2차 검증하여 벽 뚫기 공격을 무효화합니다.

자주 묻는 질문 (로블록스 공간 쿼리 및 히트박스)

GetPartsInPart가 GetTouchingParts보다 좋은 이유는 무엇인가요?

GetTouchingParts는 CanCollide가 켜져 있거나 TouchTransmitter가 생성되어 있어야 하지만, GetPartsInPart는 충돌 설정과 무관하게 OverlapParams 조건으로 즉시 교차 판정을 수행하기 때문입니다.

공격이 벽을 뚫고 타격되는 버그를 어떻게 막나요?

공격자의 위치에서 피격자의 위치로 짧은 레이캐스트를 쏘아 중간에 맵 지형이 감지되면 판정을 무효화하는 2차 검증을 추가하면 됩니다.

클라이언트가 공간 쿼리를 변조할 수 있나요?

서버 스크립트에서 실행되는 공간 쿼리는 클라이언트가 절대 변조할 수 없습니다. 판정 로직과 사거리 체크를 서버에 두면 안전합니다.
