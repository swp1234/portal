Les mondes ouverts complexes sur Roblox génèrent souvent de lourdes chutes de FPS sur mobile en raison de maillages trop denses et d'un excès d'appels de rendu (Draw Calls).

En mettant en place une architecture LOD combinant `RenderFidelity.Performance`, des gestionnaires de distance en Luau et des imposteurs 2D, votre jeu conserve 60 FPS constants sur tous les appareils.

1. Le Goulot d'Étranglement GPU : Draw Calls et Polygones

Contraintes matérielles du moteur de rendu de Roblox :

  • Surcharge des Draw Calls : Dépasser 1 500 appels par image surcharge immédiatement les processeurs mobiles.
  • Gaspillage de polygones : Calculer des milliers de sommets sur des arbres lointains est inutile.
  • Changements fréquents de textures : Ralentit considérablement le traitement de la carte graphique.
  • Étranglement thermique : La surchauffe force les smartphones à réduire leur cadence après quelques minutes.

2. RenderFidelity et Système LOD Intégré de Roblox

Exploiter au maximum la réduction géométrique automatique :

  • `RenderFidelity.Precise` : Conserve la totalité du maillage ; à réserver aux objets vus de près.
  • `RenderFidelity.Performance` : Crée 4 niveaux automatiques de détail en fonction de la taille à l'écran.
  • `CollisionFidelity.Box` : Simplifier les boîtes de collision pour soulager le processeur.
  • Instanciation automatique : Regroupe le rendu des maillages identiques partageant les mêmes matériaux.
Gestionnaire de LOD et Imposteurs 2D en Luau
--!strict
local RunService = game:GetService("RunService")
local Workspace = game:GetService("Workspace")

local LODManager = {}
type LODModel = { HighDetail: Model, LowDetail: Model, Impostor: BillboardGui, Position: Vector3, CurrentTier: number }
local registeredLODs: {LODModel} = {}

function LODManager.Register(high: Model, low: Model, impostor: BillboardGui, centerPos: Vector3)
    table.insert(registeredLODs, { HighDetail = high, LowDetail = low, Impostor = impostor, Position = centerPos, CurrentTier = 1 })
    low.Parent = nil
    impostor.Enabled = false
end

local frameCounter = 0
RunService.Heartbeat:Connect(function()
    frameCounter += 1
    if frameCounter % 6 ~= 0 then return end
    local camera = Workspace.CurrentCamera
    if not camera then return end
    local camPos = camera.CFrame.Position
    for _, lod in ipairs(registeredLODs) do
        local offset = lod.Position - camPos
        local distSq = offset.X * offset.X + offset.Y * offset.Y + offset.Z * offset.Z
        local newTier = distSq > 640000 and 4 or (distSq > 122500 and 3 or (distSq > 14400 and 2 or 1))
        if newTier ~= lod.CurrentTier then
            lod.CurrentTier = newTier
            lod.HighDetail.Parent = (newTier == 1) and Workspace or nil
            lod.LowDetail.Parent = (newTier == 2) and Workspace or nil
            lod.Impostor.Enabled = (newTier == 3)
        end
    end
end)

return LODManager

3. Imposteurs 2D & Remplacement de Maillages

Remplacement de la 3D lointaine par des sprites ultra-légers :

  • Principe de l'imposteur : Au-delà de 300 studs, un objet complexe est remplacé par une image 2D sans perte visuelle.
  • Gain massif en polygones : Des forêts entières passent de millions de triangles à quelques centaines.
  • Atlas de sprites : Plusieurs imposteurs réunis sur une seule texture réduisent les appels de rendu.
  • Transition douce : Fondu de transparence pour éviter toute apparition brutale.

4. StreamingEnabled & Architecture Mémoire

Chargement dynamique pour mondes ouverts :

  • StreamingMinRadius maîtrisé : Évite les plantages mémoire lors de l'apparition des joueurs.
  • `ModelStreamingMode.Atomic` : Assure le chargement d'un seul bloc pour les véhicules et ascenseurs.
  • `ModelStreamingMode.Persistent` : Conserve les monuments clés en mémoire en permanence.
  • Gestion du manque de RAM : Réduit dynamiquement la distance d'affichage si la mémoire sature.

5. Checklist de Production Mobile

Règles pour un jeu fluide sur Roblox :

  • Regrouper les textures des décors dans des atlas 1024x1024.
  • Désactiver CastShadow sur les petits objets secondaires.
  • Vérifier au MicroProfiler que le temps d'affichage reste inférieur à 16,6 ms.
  • Tester régulièrement sur des profils de téléphones d'entrée de gamme.

Frequently Asked Questions

Quelle est la différence entre RenderFidelity et un LOD personnalisé ?

RenderFidelity allège un maillage existant, alors qu'un LOD par script peut basculer vers un sprite 2D ou masquer entièrement des modèles.

Désactiver les collisions améliore-t-il les performances graphiques ?

Oui, car cela allège les calculs de partitionnement spatial préparatoires au rendu.

Combien de Draw Calls sont acceptables sur mobile ?

Visez entre 400 et 800 appels de rendu pour éviter la surchauffe et les saccades.
