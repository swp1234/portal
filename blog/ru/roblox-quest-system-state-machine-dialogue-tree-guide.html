Квесты и диалоги — смысловой хребет любой RPG в Roblox. Без надежной архитектуры внезапный дисконнект игрока ломает весь сюжетный прогресс.

Изучая построение графов DAG для ветвления сюжета, шины событий для отслеживания целей, условные диалоги и упаковку битов в DataStore, разработчики создают отказоустойчивые игры.

1. Квесты как Ориентированные Ациклические Графы (DAG)

Построение сюжетных линий без зацикливания и тупиков:

  • Дерево условий: Задания представлены вершинами графа, открывающимися строго после закрытия всех предшествующих этапов.
  • Взаимоисключающие ветки: Выбор одной стороны блокирует альтернативные квесты без сюжетных нестыковок.
  • Топологическая сортировка: Автоматический анализ базы исключает создание неразрешимых циклических зависимостей.

2. Конечные автоматы (FSM) жизненного цикла квеста

Строгий контроль переходов исключает читерство:

  • 6 базовых состояний: Заблокирован ➔ Доступен ➔ Активен ➔ Завершен ➔ Награда получена (плюс Провален).
  • Контроль на сервере: Клиент не может объявить квест выполненным; сервер проверяет каждое действие игрока.
  • Оптимистичный отклик UI: При подтверждении с сервера интерфейс сразу отображает заполнение шкалы и проигрывает победный звук.
ServerScriptService.QuestSystem.QuestManager
-- Модуль квестового менеджера FSM
local QuestManager = {}
QuestManager.__index = QuestManager
local QuestDatabase = require(game.ReplicatedStorage.QuestDatabase)

function QuestManager.new(player, profileData)
    local self = setmetatable({}, QuestManager)
    self.Player = player
    self.ActiveQuests = profileData.ActiveQuests or {}
    self.CompletedQuests = profileData.CompletedQuests or {}
    return self
end

function QuestManager:CanStartQuest(questId)
    local data = QuestDatabase[questId]
    if not data then return false end
    if self.CompletedQuests[questId] or self.ActiveQuests[questId] then return false end
    for _, prereqId in ipairs(data.Prerequisites) do
        if not self.CompletedQuests[prereqId] then return false end
    end
    return true
end

function QuestManager:AcceptQuest(questId)
    if not self:CanStartQuest(questId) then return false end
    self.ActiveQuests[questId] = {
        Step = 1,
        Counters = table.create(#QuestDatabase[questId].Steps[1].Objectives, 0)
    }
    return true
end

return QuestManager

3. Отслеживание целей через шину событий (Signal Bus)

Разделение игровой логики и проверки выполнения заданий:

  • Единая шина событий: Вместо внедрения кода квестов в скрипты врагов генерируется общее событие EntityKilled.
  • Фильтрация сигналов: Менеджер квестов реагирует только на события, нужные активным заданиям, снижая нагрузку на процессор.
  • Составные цели: Одновременный учет сбора ресурсов и уничтожения противников через аккуратные словари счетчиков.

4. Ветвящиеся деревья диалогов с выбором решений

Интерактивные беседы с NPC, влияющие на сюжет:

  • Узловая модель реплик: Диалоги формируются из узлов, объединяющих текст персонажа, положение камеры и варианты ответов.
  • Условные ветки: Особые реплики открываются только при наличии нужных предметов или высоком уровне репутации.
  • События внутри диалога: Выдача снаряжения, запуск катсцен или начало битвы с боссом прямо из реплики.

5. Компактное сохранение в DataStore через ProfileService

Хранение сотен выполненных заданий с минимальным расходом памяти:

  • Битовые маски (Bitfields): Завершенные квесты кодируются битами внутри целых чисел (32 квеста на 4 байта).
  • Сохранение только активных срезов: В базу пишутся только текущие задания и их счетчики без лишних метаданных.
  • Миграция схем данных: Обработчики версий в ProfileService предотвращают ошибки при обновлении сюжетных цепочек.

Frequently Asked Questions

Почему квесты лучше моделировать в виде графа DAG?

Чтобы исключить циклические тупики, когда два задания требуют выполнения друг друга и блокируют игру.

Как шина событий повышает производительность?

Она избавляет от непрерывных проверок условий каждый кадр; логика срабатывает только при реальных игровых событиях.

Как спасти прогресс при резком обрыве связи?

Использованием ProfileService с блокировкой сессий для мгновенной фиксации счетчиков в памяти и базе.

Как безопасно выдавать награды через диалоги?

Отрисовывать диалог на клиенте, но саму выдачу проверять и исполнять строго на сервере через RemoteFunction.
