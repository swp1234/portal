Otimização de Budget e Throttling no Roblox DataStore: Cache, Filas e Segurança

By DopaBrain Roblox Tech Architecture Team • Updated: September 2026 • Reading Time: 9 min
Axioma de Arquitetura: Nunca utilize o Roblox DataStore como banco de dados transacional em tempo real. Altere dados na memória do servidor e salve de forma assíncrona com bloqueio de sessão.

Desenvolvedores de jogos com alto número de jogadores simultâneos no Roblox frequentemente encontram o erro "DataStore request was added to queue and dropped". Chamar GetAsync ou SetAsync a cada ação esgota o orçamento de requisições e provoca perdas de dados.

Este guia apresenta arquiteturas de produção consolidadas: monitoramento de orçamento, cache em memória com sinalizadores de alteração (dirty flags), retentativas com recuo exponencial no UpdateAsync e bloqueio de sessão para evitar duplicação de itens.

1. Limites de Orçamento e Janelas de Requisição no DataStore

O Roblox impõe cotas rigorosas baseadas na quantidade de jogadores conectados:

  • Orçamento GetAsync: 60 + (jogadores * 10) requisições por minuto no total.
  • Orçamento SetAsync / UpdateAsync: 60 + (jogadores * 10) escritas por minuto.
  • Cooldown de Escrita de 6 Segundos: Gravar na mesma chave antes de 6 segundos gera bloqueio ou descarte imediato.
  • Limite de Tamanho: 4.194.304 caracteres (4MB) por chave.

2. Cache de Sessão em Memória e Padrão Dirty Flag

Arquitetura obrigatória para títulos escaláveis:

  • Carregar na Entrada, Salvar na Saída: Leitura única ao conectar, mantendo o perfil em tabela Lua na memória RAM.
  • Modificação In-Memory: Moedas e itens atualizam apenas a tabela local, com custo zero de chamadas API.
  • Auto-Save Periódico Escalonado: Salvar a cada 120-180 segundos apenas os dados marcados como alterados (dirty).
  • Finalização Segura com BindToClose: Vincular rotinas paralelas ao game:BindToClose().

3. Production Implementation Architecture

ServerScriptService.DataStoreManager (Arquitetura de Cache e Retentativas)
-- Safe DataStore Write with Exponential Backoff and Budget Check
local DataStoreService = game:GetService("DataStoreService")
local Players = game:GetService("Players")
local PlayerDataStore = DataStoreService:GetDataStore("PlayerCore_v1")

local MAX_RETRIES = 3
local BASE_DELAY = 1.5

local function safeUpdateAsync(key, transformFunc)
    local budget = DataStoreService:GetRequestBudgetForRequestType(Enum.DataStoreRequestType.UpdateAsync)
    if budget < 5 then
        warn("[DataStore] Throttling warning: Low budget for UpdateAsync (" .. tostring(budget) .. ")")
    end
    
    local success, result
    local attempts = 0
    
    repeat
        attempts = attempts + 1
        success, result = pcall(function()
            return PlayerDataStore:UpdateAsync(key, transformFunc)
        end)
        
        if not success then
            local delayTime = BASE_DELAY * (2 ^ (attempts - 1)) + math.random() * 0.5
            warn("[DataStore] Attempt " .. attempts .. " failed: " .. tostring(result) .. ". Retrying in " .. string.format("%.2f", delayTime) .. "s")
            task.wait(delayTime)
        end
    until success or attempts >= MAX_RETRIES
    
    return success, result
end

4. Bloqueio de Sessão (Session Locking) contra Duplicação

Segurança contra exploits em trocas rápidas de servidor (server hop):

  • Exploit de Server Hop: Entrar em outro servidor antes de salvar o anterior pode duplicar itens.
  • Session Lock: Gravação do JobId e horário no perfil durante o jogo ativo.
  • Aguardando Desbloqueio: O novo servidor aguarda a liberação pelo servidor anterior.
  • Uso do ProfileService: Padrão aberto da comunidade com locking e salvamento automático nativos.

5. Migração de Esquema e Versionamento de Dados

Atualizações seguras sem perda de progresso para os jogadores:

  • Cabeçalho de Versão: Campo _SchemaVersion para rastrear mudanças.
  • Reconciliação Automática: Mesclar valores padrão em perfis antigos.
  • Limpeza Gradual: Manter retrocompatibilidade antes de remover chaves legadas.

Frequently Asked Questions

Por que ocorre o erro de cooldown de 6 segundos no Roblox?

Para preservar os servidores centrais, o motor do Roblox bloqueia escritas frequentes na mesma chave.

Qual é a vantagem do ProfileService em relação à API padrão?

Ele automatiza session locking, rotinas de auto-save e protege contra quedas repentinas de servidor.

Como testar limitações de DataStore no Studio?

Habilitando acesso à API nas configurações do jogo e monitorando GetRequestBudgetForRequestType().

Como evitar timeout de 30 segundos no BindToClose?

Executando gravações assíncronas em lotes paralelos em vez de loops sequenciais síncronos.
