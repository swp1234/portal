Manajemen inventaris adalah fondasi game RPG dan survival di Roblox. Desain yang buruk membuka celah eksploitasi duplikasi dan lag saat menyeret item di perangkat seluler.

Dengan menerapkan validasi server yang ketat, struktur data modular, dan penguncian sesi DataStore melalui ProfileService, pengembang dapat membangun ekonomi game yang aman dan responsif.

1. Model Inventaris: Slot Tetap vs. Grid Spasial vs. Beban Berat

Memilih model yang sesuai dengan alur permainan:

  • Slot Tetap: Model hotbar klasik dengan indeks array tetap. Pencarian O(1) cepat dan serialisasi data sederhana.
  • Grid Tetris Spasial: Item berukuran multi-kotak ala Diablo. Memerlukan pengujian tabrakan array 2D.
  • Anggaran Beban Berat: Setiap item memiliki massa; melebihi kapasitas memicu penalti kecepatan gerak.

2. Otoritas Server & UI Klien Optimis

Interaksi cepat tanpa kompromi keamanan:

  • Prediksi UI Optimis: Ikon berpindah secara visual seketika tanpa menunggu konfirmasi jaringan server.
  • Validasi Server: Server memverifikasi kepemilikan, batas slot, dan berat sebelum menyimpan perubahan.
  • Rollback Mulus: Jika tindakan ditolak, ikon kembali secara otomatis ke slot semula.

3. Struktur Data Item & Serialisasi Stack

Pemisahan atribut statis dan dinamis secara rapi di Luau:

  • Templat Dasar vs. Instansi: Nama dan berat disimpan di ReplicatedStorage, UUID dan durabilitas di data pemain.
  • Penggabungan Stack: Menghitung sisa ruang slot target dan mentransfer jumlah item secara aman.
  • Kompresi Penyimpanan: Mengabaikan slot kosong saat penyimpanan agar tidak melampaui batas 4MB DataStore.
ServerScriptService.Inventory.InventoryManager
-- Pengelola Inventaris Otoritatif Server
local InventoryManager = {}
InventoryManager.__index = InventoryManager
local ItemDatabase = require(game.ReplicatedStorage.ItemDatabase)

function InventoryManager.new(player, maxSlots, maxWeight)
    local self = setmetatable({}, InventoryManager)
    self.Player = player
    self.MaxSlots = maxSlots or 30
    self.MaxWeight = maxWeight or 100
    self.Slots = table.create(self.MaxSlots, false)
    self.CurrentWeight = 0
    self.IsLocked = false
    return self
end

function InventoryManager:AddItem(itemId, amount)
    if self.IsLocked then return false, "INVENTORY_LOCKED" end
    local itemData = ItemDatabase[itemId]
    if not itemData then return false, "INVALID_ITEM" end
    local addedWeight = itemData.Weight * amount
    if self.CurrentWeight + addedWeight > self.MaxWeight then
        return false, "OVER_ENCUMBERED"
    end
    for slotIndex = 1, self.MaxSlots do
        local slot = self.Slots[slotIndex]
        if slot and slot.Id == itemId and slot.Count < itemData.MaxStack then
            local space = itemData.MaxStack - slot.Count
            local toAdd = math.min(space, amount)
            slot.Count = slot.Count + toAdd
            amount = amount - toAdd
            self.CurrentWeight = self.CurrentWeight + (itemData.Weight * toAdd)
            if amount <= 0 then return true end
        end
    end
    for slotIndex = 1, self.MaxSlots do
        if not self.Slots[slotIndex] then
            self.Slots[slotIndex] = {
                UUID = game:GetService("HttpService"):GenerateGUID(false),
                Id = itemId,
                Count = amount,
                Durability = itemData.MaxDurability
            }
            self.CurrentWeight = self.CurrentWeight + (itemData.Weight * amount)
            return true
        end
    end
    return false, "INVENTORY_FULL"
end

return InventoryManager

4. Keamanan Anti-Duplikasi dengan ProfileService

Mencegah eksploitasi crash dan perdagangan ganda:

  • Session Lock MemoryStore: Kunci terdistribusi sementara saat item ditransfer untuk mencegah double-spend.
  • Transaksi Barter Atomik: Pertukaran dieksekusi dalam satu frame server atau dibatalkan sepenuhnya jika terjadi putus koneksi.
  • Pembatasan Frekuensi Permintaan: Cooldown minimal 100ms untuk menahan serangan banjir paket.

5. UX Layar Sentuh & Responsivitas Mobile

Navigasi nyaman di ponsel dan tablet:

  • Target Sentuh Minimal 44px: Penyesuaian skala dinamis untuk mencegah salah sentuh di layar kecil.
  • Menu Melingkar Tekan-Lama: Pengganti klik kanan di perangkat sentuh untuk opsi Gunakan, Bagi, atau Buang.
  • Umpan Balik Haptik: Getaran halus melalui HapticService saat memasang perlengkapan.

Frequently Asked Questions

Mengapa logika inventaris harus berada di server?

Logika di klien memungkinkan peretas memalsukan item dan menduplikasi aset. Server menjamin keaslian data ekonomi.

Bagaimana UI optimis menghilangkan jeda waktu?

Ikon bergerak langsung di layar pemain, dan hanya ditarik kembali jika server menolak permintaan perpindahan.

Apa itu penguncian sesi DataStore?

Sistem yang memastikan hanya satu server yang dapat menulis data pemain dalam satu waktu guna mencegah duplikasi aset.

Bagaimana cara mencegah sentuhan tersendat di ponsel?

Gunakan ikon tiruan ringan selama jari bergerak dan periksa slot tujuan hanya saat sentuhan dilepaskan.
