로블록스 레이어드 의류 아키텍처: WrapLayer, WrapTarget, 케이지 메쉬와 HSR 최적화

By DopaBrain 로블록스 시스템 엔지니어링 팀 • 2026-09-30 • Technical Guide
아바타 시스템 공학 원칙: 고정된 정적 3D 의류는 다양한 체형의 아바타를 만났을 때 살을 뚫고 튀어나오거나 모바일 기기에서 불필요한 폴리곤 렌더링 렉을 유발합니다. 현대 로블록스 대작 타이틀은 케이지 메쉬(Cage Mesh) 변형과 엔진 자동 은면 제거(HSR) 기술을 결합하여 무결점 핏을 구현합니다.

뇌 유형 테스트 3D 공간 기하학 및 케이지 변형 인지 모델링 스타일 2048 코치 메시 토폴로지 최적화 및 정점 예산 자원 배분 훈련 반응속도 테스트 실시간 아바타 렌더링 및 의류 변형 연산 지연율 측정 스트레스 지수 3D 리깅 파이프라인 복잡도와 의류 클리핑 디버깅 피로도

아바타 커스터마이징은 로블록스 생태계에서 유저 몰입도, 사회적 표현, 유저 잔존율(Retention)을 견인하는 핵심 요소입니다. 그러나 커스텀 옷이 몸을 뚫고 나오거나, 여러 겹의 옷이 서로 겹쳐 깨지는 클리핑(Clipping) 현상은 게임의 완성도를 떨어뜨립니다.

로블록스의 레이어드 의류(Layered Clothing) 시스템은 WrapTarget과 WrapLayer, 그리고 이중 케이지 메쉬(Inner Cage와 Outer Cage)를 기반으로 작동합니다. 체계적인 레이어 스택(Order), 볼륨감(Puffiness), 그리고 은면 제거(HSR) 원리를 이해하면 어떤 체형에서도 완벽하게 감싸지는 고급 의상 시스템을 구축할 수 있습니다.

1. 케이지 메쉬 변형 아키텍처: Inner Cage와 Outer Cage

레이어드 의류가 다양한 신체 형태에 맞춰 유기적으로 변형되는 원리:

  • 이너 케이지(Inner Cage): 마네킹의 기본 신체 표면을 정의하며, 옷의 버텍스가 아바타의 신체 비율을 감지하고 안착하는 기준면 역할을 합니다.
  • 아우터 케이지(Outer Cage): 해당 옷 위에 덧입혀질 다음 겉옷이 놓일 바깥 경계면을 정의하여, 외투가 안쪽 셔츠를 파고드는 현상을 물리적으로 방지합니다.
  • WrapTarget vs WrapLayer: WrapTarget은 기본 아바타 신체 파츠에 장착되어 기준면을 제공하고, WrapLayer는 옷 액세서리 내부에 위치하여 실시간 변형 연산을 수신합니다.

2. 레이어 순서(Order)와 볼륨감(Puffiness) 계층 구조

다중 의류 착용 시 클리핑 없이 자연스러운 옷맵시를 유지하는 법:

  • Order 속성 계층화: 속옷(1) ➔ 티셔츠(2) ➔ 후드티(3) ➔ 롱패딩(4) ➔ 전술 조끼(5) 순으로 정수 우선순위를 부여하여, 안쪽 옷이 바깥 옷을 밀어내며 감싸지도록 강제합니다.
  • Puffiness 튜닝 (-1.0 ~ 1.0): 외투의 두께감과 부풀림 정도를 조절하여, 두꺼운 겨울 파카가 안쪽의 무기 벨트나 두꺼운 갑옷 위에 자연스럽게 얹히도록 제어합니다.
  • 레퍼런스 메쉬(ReferenceMesh) 정렬: UV 텍스처 좌표와 변형 행렬을 1:1 매핑하여, 관절이 격렬하게 꺾여도 옷감의 체크무늬나 로고가 일그러지지 않도록 방지합니다.
ServerScriptService.Avatar.LayeredClothingManager
-- 서버 권한 레이어드 의류 착용 및 크기 검증 모듈
local LayeredClothingManager = {}
LayeredClothingManager.__index = LayeredClothingManager

local MAX_ACCESSORY_BOUNDS = Vector3.new(6, 6, 6)

function LayeredClothingManager.EquipGarment(character, accessoryTemplate, layerOrder)
    local humanoid = character:FindFirstChildOfClass("Humanoid")
    if not humanoid then return false end

    -- 시야 방해 트롤링 방지를 위한 크기 한계 검증
    local handle = accessoryTemplate:FindFirstChild("Handle")
    if not handle or handle.Size.Magnitude > MAX_ACCESSORY_BOUNDS.Magnitude then
        warn("[LayeredClothing] Rejected oversized accessory from " .. character.Name)
        return false
    end

    local wrapLayer = handle:FindFirstChildOfClass("WrapLayer")
    if wrapLayer then
        wrapLayer.Order = layerOrder
    end

    -- 복제 및 캐릭터 부착
    local newAccessory = accessoryTemplate:Clone()
    humanoid:AddAccessory(newAccessory)
    return true
end

return LayeredClothingManager

3. 은면 제거 (HSR, Hidden Surface Removal) 및 GPU 최적화

여러 겹의 옷 아래 가려진 보이지 않는 수만 개의 폴리곤 드로우 콜 제거:

  • 엔진 레벨 자동 HSR: 로블록스는 불투명한 겉옷에 의해 완전히 가려진 안쪽 옷과 아바타 신체의 삼각형 폴리곤을 실시간 감지하여 GPU 렌더링에서 자동 제외합니다.
  • HSR 결함 방지 수칙: 겉옷 3D 메쉬에 눈에 보이지 않는 미세한 구멍(Hole)이나 분리된 버텍스가 존재하면 HSR 연산이 실패하여 알몸 텍스처가 순간 노출되는 버그가 발생하므로 닫힌 지오메트리를 보장해야 합니다.
  • 메모리 예산 관리: 액세서리당 버텍스 수를 4,000개 이하로 제한하여 2GB RAM 모바일 기기에서의 VRAM 과부하 크래시를 원천 차단합니다.

4. 런타임 의상 교체 파이프라인 (HumanoidDescription)

게임 진행 중 랙이나 깜빡임 없이 부드럽게 의상을 교체하는 Luau 로직:

  • HumanoidDescription 활용: Humanoid:ApplyDescription()을 통해 로블록스 클라우드 아바타 파이프라인과 네이티브 동기화하여 레이어드 의류를 안전하게 착용합니다.
  • 커스텀 인벤토리 컨트롤러: 게임 내에서 자체 제작한 Accessory 모델을 복제하고 캐릭터 바디 어태치먼트에 직접 마운트하여 실시간 의상 변경을 구현합니다.
  • 변형 워밍업 가드: 메쉬가 완전히 변형되기 전에 화면에 노출되면 1프레임 동안 옷이 T포즈로 튀는 팝인(Pop-in) 현상이 발생하므로, WrapLayer.DeformedMeshCreated 신호 수신 후 가시성을 켭니다.

5. 안티 치트 및 시야 방해 어뷰징 차단

비정상적으로 거대한 의류로 화면을 가리는 트롤링 방지 규칙:

  • 바운딩 박스 볼륨 검증: 서버에서 장착 요청된 의류의 Handle 크기를 검사하여, 6x6x6 스터드를 초과하는 거대 UGC 트롤링 아이템을 즉각 기각합니다.
  • Order 스푸핑 차단: 악성 클라이언트가 임의의 비정상적인 Order 번호를 주입하여 그래픽 엔진을 깨뜨리지 못하도록 서버 화이트리스트 슬롯 검증을 적용합니다.
  • DataStore 압축 저장: 유저가 착용한 의상 정보를 무거운 메쉬 인스턴스 대신 64비트 에셋 ID 배열로 직렬화하여 바이트 사용량을 95% 이상 절감합니다.

Frequently Asked Questions

로블록스 WrapTarget과 WrapLayer의 차이는 무엇인가요?

WrapTarget은 아바타의 신체 파츠에 부착되어 기준 표면을 제공하며, WrapLayer는 옷 액세서리에 장착되어 WrapTarget의 형상에 맞춰 버텍스 변형을 계산합니다.

레이어드 의류의 Order 속성은 어떻게 작동하나요?

Order는 옷이 겹쳐지는 순서를 지정하는 정수입니다. 낮은 번호(예: 티셔츠 2번)의 옷 위에 높은 번호(예: 코트 4번)의 옷이 덧입혀져 클리핑을 방지합니다.

은면 제거(HSR)가 왜 모바일 성능에 결정적인가요?

겉옷에 완전히 가려져 보이지 않는 수천 개의 신체 및 안쪽 옷 폴리곤을 GPU 연산에서 제외하여 렌더링 부하와 메모리 소비를 대폭 줄여주기 때문입니다.

어떤 옷들은 착용 시 왜 기괴하게 늘어나거나 찌그러지나요?

3D 모델링 단계에서 옷의 Inner Cage가 아바타의 표준 마네킹과 일치하지 않거나, 버텍스 스키닝 웨이트가 잘못 칠해졌을 때 발생합니다.

유저들이 거대한 옷을 만들어 화면을 가리는 트롤링을 어떻게 막나요?

서버 측에서 장착 요청된 액세서리 Handle의 바운딩 박스 크기와 Puffiness 수치를 검사하여 허용 한도를 넘는 아이템을 장착 거부합니다.
