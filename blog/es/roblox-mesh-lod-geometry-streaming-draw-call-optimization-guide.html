Los mundos abiertos masivos en Roblox suelen provocar caídas graves de rendimiento en móviles debido a un exceso de polígonos y llamadas de dibujado (Draw Calls).

Con una tubería de LOD estructurada que combine `RenderFidelity.Performance`, reemplazo procedural en Luau e impostores en 2D, es posible garantizar 60 FPS en cualquier dispositivo.

1. El Cuello de Botella Gráfico: Draw Calls y Polígonos

Límites de hardware en el motor de renderizado de Roblox:

  • Sobrecarga de llamadas de dibujado: Superar 1.500 llamadas satura rápidamente las CPUs móviles.
  • Desperdicio de vértices: Calcular miles de polígonos en árboles lejanos que ocupan pocos píxeles es ineficiente.
  • Cambios de textura constantes: La falta de atlas de texturas detiene la GPU continuamente.
  • Estrangulamiento térmico: El uso excesivo de GPU reduce la velocidad del procesador en minutos.

2. RenderFidelity y el Sistema LOD Nativo de Roblox

Aprovechando la simplificación geométrica automática:

  • `RenderFidelity.Precise`: Mantiene el 100% de la geometría; reservar para objetos de vista en primera persona.
  • `RenderFidelity.Performance`: Genera automáticamente 4 niveles de detalle geométrico según el tamaño en pantalla.
  • `CollisionFidelity.Box`: Simplificar colisiones en elementos decorativos para liberar la CPU física.
  • Instanciación automática: Mallas idénticas con mismos materiales se dibujan en un único paquete.
Gestor Luau de LOD por Distancia e Impostores 2D
--!strict
local RunService = game:GetService("RunService")
local Workspace = game:GetService("Workspace")

local LODManager = {}
type LODModel = { HighDetail: Model, LowDetail: Model, Impostor: BillboardGui, Position: Vector3, CurrentTier: number }
local registeredLODs: {LODModel} = {}

function LODManager.Register(high: Model, low: Model, impostor: BillboardGui, centerPos: Vector3)
    table.insert(registeredLODs, { HighDetail = high, LowDetail = low, Impostor = impostor, Position = centerPos, CurrentTier = 1 })
    low.Parent = nil
    impostor.Enabled = false
end

local frameCounter = 0
RunService.Heartbeat:Connect(function()
    frameCounter += 1
    if frameCounter % 6 ~= 0 then return end
    local camera = Workspace.CurrentCamera
    if not camera then return end
    local camPos = camera.CFrame.Position
    for _, lod in ipairs(registeredLODs) do
        local offset = lod.Position - camPos
        local distSq = offset.X * offset.X + offset.Y * offset.Y + offset.Z * offset.Z
        local newTier = distSq > 640000 and 4 or (distSq > 122500 and 3 or (distSq > 14400 and 2 or 1))
        if newTier ~= lod.CurrentTier then
            lod.CurrentTier = newTier
            lod.HighDetail.Parent = (newTier == 1) and Workspace or nil
            lod.LowDetail.Parent = (newTier == 2) and Workspace or nil
            lod.Impostor.Enabled = (newTier == 3)
        end
    end
end)

return LODManager

3. Impostores 2D y Almacenamiento en Texturas

Reemplazo de geometría 3D por planos 2D a gran distancia:

  • Concepto impostor: A más de 300 studs, un edificio complejo se reduce a un simple plano con textura sin pérdida visual.
  • Ahorro brutal de polígonos: Miles de árboles pasan de millones de vértices a unos pocos cientos.
  • Compartir texturas: Varios impostores en una misma hoja reducen drásticamente las llamadas de dibujado.
  • Transición por difuminado: Evita que los objetos aparezcan o desaparezcan bruscamente.

4. StreamingEnabled y Control de Memoria

Carga dinámica de terrenos masivos:

  • StreamingMinRadius reducido: Evita cierres de aplicación por falta de memoria al aparecer.
  • `ModelStreamingMode.Atomic`: Carga vehículos y mecanismos interactivos como un bloque indivisible.
  • `ModelStreamingMode.Persistent`: Mantiene cargados los puntos de referencia principales del mapa.
  • Respuesta a memoria baja: Reducir distancias de dibujado dinámicamente si el dispositivo avisa de falta de RAM.

5. Checklist de Optimización Móvil

Pautas para publicar juegos fluidos en Roblox:

  • Agrupar texturas de objetos pequeños en atlas de 1024x1024 píxeles.
  • Desactivar CastShadow en objetos decorativos secundarios.
  • Monitorizar con MicroProfiler que el tiempo por cuadro no supere 16.6 ms.
  • Probar en perfiles de dispositivos de gama baja antes del lanzamiento.

Frequently Asked Questions

¿Qué ventaja tiene un LOD por script frente a RenderFidelity?

El LOD por script permite sustituir modelos completos por texturas planas en 2D o apagarlos completamente a gran distancia.

¿Desactivar colisiones mejora la velocidad gráfica?

Sí, porque agiliza las comprobaciones espaciales previas al renderizado en el motor.

¿Cuál es el límite seguro de Draw Calls para móviles?

Entre 400 y 800 llamadas. Superar 1.200 provocará caídas notorias de FPS y calentamiento.
