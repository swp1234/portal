대규모 오픈월드 RPG, 도시 롤플레잉, 배틀로얄 게임을 제작할 때 가장 큰 장벽은 모바일 기기의 메모리 한계입니다. 로블록스 접속자의 60% 이상은 RAM 3GB 이하의 스마트폰으로 접속하므로, 전체 맵을 한 번에 로드하면 앱이 강제 종료됩니다.

로블록스의 StreamingEnabled 기능은 플레이어와의 거리에 따라 3D 인스턴스를 동적으로 불러오고 메모리에서 제거합니다. 그러나 단순 활성화 시 클라이언트 스크립트에서 오브젝트를 찾지 못해 오류가 발생합니다. 본 가이드에서는 StreamOutBehavior, ModelStreamingMode, RequestStreamAroundAsync 활용법을 상세히 다룹니다.

1. StreamingEnabled 원리: 반경 설정과 메모리 회수

로블록스 엔진이 동적으로 월드 데이터를 관리하는 방식:

  • StreamingTargetRadius: 플레이어 주변에서 활성화되어 렌더링될 최대 반경(Stud 단위).
  • StreamingMinRadius: 어떠한 메모리 부족 상황에서도 절대 스트림 아웃되지 않는 핵심 내부 반경.
  • StreamOutBehavior (Opportunistic): 모바일 기기의 RAM이 부족해질 때 엔진이 먼 거리의 청크를 자동으로 언로드하여 앱 강제 종료를 차단합니다.
  • StreamingPauseMode: 고속 차량 이동이나 순간이동 시 스트리밍 속도가 플레이어를 따라가지 못할 때 물리 연산을 멈추고 안전하게 대기시킵니다.

2. ModelStreamingMode: 모델 단위 스트리밍 제어

복잡한 오브젝트의 온전성을 보장하는 4가지 모드:

  • Default: 모델의 자식 파트들이 개별적으로 로드/언로드되어 문이나 기계 장치가 반만 로드되는 문제가 생길 수 있습니다.
  • Atomic: 모델과 모든 자식 파트가 하나의 덩어리로 동시에 로드되고 언로드됩니다. 상호작용 문, 퍼즐 기믹에 필수적입니다.
  • Persistent: 거리에 상관없이 플레이어 접속 시 영구 로드되며 절대 언로드되지 않습니다. 핵심 거점이나 글로벌 인터페이스에만 제한적으로 사용합니다.
  • PersistentPerPlayer: 서버 스크립트를 통해 특정 플레이어에게만 퀘스트 마커나 개인 하우징 모델을 고정 로드할 수 있습니다.

3. Production Implementation Architecture

StarterPlayer.StarterPlayerScripts.StreamingObjectBinder
-- Streaming-Resilient Tag Binder using CollectionService
local CollectionService = game:GetService("CollectionService")
local Workspace = game:GetService("Workspace")

local TAG_NAME = "InteractiveNPC"

local function onObjectStreamedIn(instance)
    if not instance:IsA("Model") then return end
    
    -- Ensure primary part exists before attaching UI
    local primaryPart = instance.PrimaryPart or instance:WaitForChild("HumanoidRootPart", 5)
    if not primaryPart then return end
    
    print("[Streaming] Interactive object loaded: " .. instance.Name)
    -- Attach billboard prompt or local animation controller
end

local function onObjectStreamedOut(instance)
    print("[Streaming] Interactive object unloaded: " .. instance.Name)
    -- Clean up any active local tweens, highlights, or sound emitters
end

CollectionService:GetInstanceAddedSignal(TAG_NAME):Connect(onObjectStreamedIn)
CollectionService:GetInstanceRemovedSignal(TAG_NAME):Connect(onObjectStreamedOut)

-- Initial sweep for parts already streamed in upon join
for _, obj in ipairs(CollectionService:GetTagged(TAG_NAME)) do
    task.spawn(onObjectStreamedIn, obj)
end

4. 텔레포트 낙하 버그 해결: RequestStreamAroundAsync

원거리 순간이동 시 맵 밑으로 추락하는 현상 완벽 방지:

  • 지형 미로드 추락 위험: 먼 위치로 즉시 CFrame을 이동시키면 지형이 로드되기 전에 캐릭터가 허공으로 추락합니다.
  • 사전 청크 스트리밍 요청: 서버 측에서 이동 전에 player:RequestStreamAroundAsync(targetCFrame.Position, 10)를 호출하여 주변 지형을 먼저 로드합니다.
  • 이동 간 물리 고정: 지형 로드가 확인될 때까지 HumanoidRootPart.Anchored = true로 고정한 후 안전하게 해제합니다.

5. 에셋 예산: LOD와 텍스처 아틀라스 최적화

스트리밍과 결합하여 그래픽 품질과 메모리를 동시에 잡는 기법:

  • 메시 LOD (RenderFidelity): MeshPart의 RenderFidelity를 Performance로 설정하여 원거리에서 저폴리곤 모델로 자동 전환합니다.
  • 텍스처 아틀라싱: 여러 건물 텍스처를 2048x2048 한 장의 아틀라스로 통합하여 Draw Call과 VRAM 사용량을 대폭 절감합니다.
  • 지형 메시 대체: 플레이어가 갈 수 없는 원경의 복잡한 복셀 지형은 가벼운 저폴리곤 배경 메시로 대체합니다.

Frequently Asked Questions

스트리밍이네이블을 켜면 기존 스크립트가 왜 깨지나요?

플레이어와 멀리 떨어진 오브젝트가 클라이언트 Workspace에 존재하지 않기 때문에, 직접 참조하던 스크립트가 nil 인덱싱 오류를 일으킵니다. CollectionService 이벤트를 활용해 동적으로 연결해야 합니다.

Atomic 모드와 Persistent 모드의 성능 차이는 무엇인가요?

Atomic은 모델 전체가 한 번에 로드/언로드되어 메모리를 아낄 수 있지만, Persistent는 항상 클라이언트 RAM에 상주하므로 과도하게 사용하면 모바일 튕김의 원인이 됩니다.

StreamingEnabled가 모바일 튕김을 줄이는 이유는?

10,000 Stud 이상의 거대한 맵이라도 플레이어 주변 200~500 Stud의 데이터만 RAM에 유지하므로 클라이언트 메모리 점유율을 800MB 이하로 제어할 수 있기 때문입니다.

서버 스크립트에서도 스트림 아웃된 파트에 접근할 수 없나요?

아닙니다! 서버는 전체 월드의 완전한 복사본을 메모리에 항상 유지합니다. StreamingEnabled는 서버에서 클라이언트로의 데이터 전송에만 관여합니다.
