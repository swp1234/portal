Crear mundos abiertos masivos en Roblox presenta un gran desafío: más del 60% de los usuarios juegan desde teléfonos móviles con menos de 3GB de RAM. Cargar mapas enteros de forma simultánea provoca cierres por falta de memoria (OOM).

StreamingEnabled replica instancias 3D dinámicamente según la proximidad del jugador. Sin embargo, requiere adaptar los scripts del cliente para evitar errores por partes aún no cargadas. Aprende a configurar ModelStreamingMode y RequestStreamAroundAsync.

1. Mecánica de StreamingEnabled: Radios y Liberación de Memoria

Control dinámico de la geometría del mapa en Roblox:

  • StreamingTargetRadius: Radio máximo en studs donde los objetos se cargan y renderizan.
  • StreamingMinRadius: Área esencial alrededor del personaje que nunca se descarga.
  • StreamOutBehavior: Descarga fragmentos lejanos de forma oportunista ante escasez de RAM móvil.
  • StreamingPauseMode: Pausa la física de manera controlada durante movimientos a gran velocidad.

2. ModelStreamingMode: Modos de Replicación para Modelos

Garantizar la integridad de modelos y mecanismos interactivos:

  • Default: Las piezas se descargan de forma independiente, pudiendo fragmentar objetos.
  • Atomic: El modelo y todas sus piezas se cargan o descargan como un bloque único e indivisible.
  • Persistent: Se carga al conectar y permanece siempre en memoria. Usar solo en puntos críticos.
  • PersistentPerPlayer: Permite fijar modelos individualmente para jugadores específicos desde el servidor.

local Workspace = game:GetService("Workspace")

local TAG_NAME = "InteractiveNPC"

local function onObjectStreamedIn(instance)
    if not instance:IsA("Model") then return end

    -- Ensure primary part exists before attaching UI
    local primaryPart = instance.PrimaryPart or instance:WaitForChild("HumanoidRootPart", 5)
    if not primaryPart then return end

    print("[Streaming] Interactive object loaded: " .. instance.Name)
    -- Attach billboard prompt or local animation controller
end

local function onObjectStreamedOut(instance)
    print("[Streaming] Interactive object unloaded: " .. instance.Name)
    -- Clean up any active local tweens, highlights, or sound emitters
end

CollectionService:GetInstanceAddedSignal(TAG_NAME):Connect(onObjectStreamedIn)
CollectionService:GetInstanceRemovedSignal(TAG_NAME):Connect(onObjectStreamedOut)

-- Initial sweep for parts already streamed in upon join
for _, obj in ipairs(CollectionService:GetTagged(TAG_NAME)) do
    task.spawn(onObjectStreamedIn, obj)
end

4. Teletransporte Seguro: RequestStreamAroundAsync

Eliminar el error de caída al vacío al cambiar de posición:

  • El Peligro del Vacío: Mover al jugador antes de cargar el suelo causa caídas interminables.
  • Precarga de Geometría: Ejecutar player:RequestStreamAroundAsync() antes de mover el CFrame.
  • Anclaje Temporal: Fijar el personaje con Anchored hasta confirmar la carga del terreno.

5. Presupuesto de Recursos: LOD y Atlas de Texturas

Optimización gráfica para entornos de gran escala:

  • Mesh LOD: Configurar RenderFidelity en Performance para reducir polígonos a distancia.
  • Atlas de Texturas: Fusionar texturas en lienzos de 2048x2048 para reducir llamadas de dibujado.
  • Sustitución de Terreno: Usar modelos de fondo de baja resolución para montañas inaccesibles.

Frequently Asked Questions

¿Por qué fallan los scripts con StreamingEnabled activado?

Porque los objetos distantes no existen en el cliente hasta que el jugador se acerca. Acceder a ellos directamente genera errores de tipo nil.

¿Cuál es la diferencia entre Atomic y Persistent?

Atomic ahorra memoria descargando el modelo completo a distancia; Persistent lo mantiene permanentemente en RAM.

¿Cómo evita StreamingEnabled el cierre en móviles?

Al mantener solo unos cientos de studs en memoria simultáneamente, el consumo de RAM se mantiene bajo 800MB.

¿Puede el servidor acceder a partes descargadas en el cliente?

Sí, el servidor conserva siempre el mundo completo en su memoria; el streaming solo afecta la replicación hacia el cliente.
