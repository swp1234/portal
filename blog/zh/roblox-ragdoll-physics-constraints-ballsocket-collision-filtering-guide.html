布娃娃（Ragdoll）物理能够将角色受击、击飞、高空坠落转化为极具沉浸感与趣味性的动态物理反馈。然而，欠缺优化的布娃娃系统极易引发肢体剧烈抽搐抖动、严重的网络橡皮筋回拉（Rubber-banding）甚至角色直接穿透地面跌出虚空等灾难性漏洞。

构建商业级成熟的布娃娃系统，必须通过 BallSocketConstraint 严格锁定人体解剖学关节角限位，利用 NoCollisionConstraint 根除肢体间自碰撞冲击波，精确分配 NetworkOwnership 归属，并设计无缝衔接的起身状态机将倒地角色平滑插值回骨骼动画。

1. Motor6D 动态切换与 BallSocketConstraint 旋转限位

将动画驱动的刚性骨骼平滑无缝转化为物理引擎驱动的柔性铰链：

  • Motor6D 禁用机制：将连接四肢与躯干的 Motor6D 设为 Enabled = false，切勿直接 Destroy()，否则后续无法恢复站立姿态。
  • BallSocketConstraint 角度极限：开启 LimitsEnabled 与 TwistLimitsEnabled。UpperAngle 限制肢体反向超屈，TwistLowerAngle 与 TwistUpperAngle 杜绝小臂或小腿发生 360 度麻花式怪异反转。
  • Attachment 预制缓存：在角色刚 Spawn 生成时预先在关节处创建好 Attachment0 与 Attachment1，避免在受击布娃娃瞬间因创建实例造成掉帧。
  • Humanoid 状态机接管：将 Humanoid 状态切换为 Enum.HumanoidStateType.Physics，并在跌落期间临时禁用 GettingUp 状态，防止动作动画与物理刚体争抢控制权。

2. 碰撞组隔离与 NoCollisionConstraint 自碰撞抑制

彻底解决肢体间穿模挤压产生的超强反冲斥力：

  • 自碰撞爆炸效应 (Self-Collision Chaos)：当多个开启了物理碰撞的肢体在跌落过程中发生穿模重叠，物理求解器会产生数万数值的排斥冲量，将角色瞬间弹射上天。
  • NoCollisionConstraint 配对：在所有相邻骨骼（如左大腿与左小腿、躯干与上臂）之间建立 NoCollisionConstraint，物理引擎将彻底跳过两者间的接触检测。
  • CollisionFilteringService 隔离：将处于布娃娃状态的部件归入专用的 "RagdollCharacters" 碰撞组，配置为仅与静态地面墙体碰撞，忽略其他角色的碰撞体积。
  • CanCollide 精细化配置：关闭 HumanoidRootPart 的 CanCollide，仅保留 Torso 的碰撞属性，确保角色在地面顺畅翻滚而不被根节点卡绊。
具备平滑起身特性的 Luau 生产级布娃娃管理系统
--!strict
local Players = game:GetService("Players")
local PhysicsService = game:GetService("PhysicsService")

local RagdollManager = {}
RagdollManager.__index = RagdollManager

type RagdollRig = {
    character: Model,
    humanoid: Humanoid,
    rootPart: BasePart,
    motors: { Motor6D },
    constraints: { BallSocketConstraint },
}

function RagdollManager.SetupRig(character: Model): RagdollRig
    local humanoid = character:WaitForChild("Humanoid") :: Humanoid
    local rootPart = character:WaitForChild("HumanoidRootPart") :: BasePart
    local motors: { Motor6D } = {}
    local constraints: { BallSocketConstraint } = {}

    for _, desc in ipairs(character:GetDescendants()) do
        if desc:IsA("Motor6D") and desc.Name ~= "Root" then
            table.insert(motors, desc)

            local part0 = desc.Part0
            local part1 = desc.Part1
            if part0 and part1 then
                -- 预建连接点
                local att0 = Instance.new("Attachment")
                att0.CFrame = desc.C0
                att0.Name = "RagdollAtt_" .. desc.Name
                att0.Parent = part0

                local att1 = Instance.new("Attachment")
                att1.CFrame = desc.C1
                att1.Name = "RagdollAtt_" .. desc.Name
                att1.Parent = part1

                -- 球窝铰链约束
                local bsc = Instance.new("BallSocketConstraint")
                bsc.Attachment0 = att0
                bsc.Attachment1 = att1
                bsc.LimitsEnabled = true
                bsc.UpperAngle = 45
                bsc.TwistLimitsEnabled = true
                bsc.TwistLowerAngle = -30
                bsc.TwistUpperAngle = 30
                bsc.Enabled = false
                bsc.Parent = part0
                table.insert(constraints, bsc)

                -- 相邻肢体防穿模排斥
                local ncc = Instance.new("NoCollisionConstraint")
                ncc.Part0 = part0
                ncc.Part1 = part1
                ncc.Parent = part0
            end
        end
    end

    return {
        character = character,
        humanoid = humanoid,
        rootPart = rootPart,
        motors = motors,
        constraints = constraints,
    }
end

function RagdollManager.EnableRagdoll(rig: RagdollRig)
    rig.humanoid:ChangeState(Enum.HumanoidStateType.Physics)
    rig.rootPart.CanCollide = false

    for _, motor in ipairs(rig.motors) do
        motor.Enabled = false
    end
    for _, bsc in ipairs(rig.constraints) do
        bsc.Enabled = true
    end
end

function RagdollManager.DisableRagdoll(rig: RagdollRig)
    for _, bsc in ipairs(rig.constraints) do
        bsc.Enabled = false
    end
    for _, motor in ipairs(rig.motors) do
        motor.Enabled = true
    end

    rig.rootPart.CanCollide = true
    rig.humanoid:ChangeState(Enum.HumanoidStateType.GettingUp)
end

return RagdollManager

3. 网络所有权 (Network Ownership) 与复制确定性

物理模拟由哪台设备计算，直接决定了其他玩家眼中画面的流畅度：

  • 本地玩家网络所有权：玩家自身角色布娃娃化时，调用 `BasePart:SetNetworkOwner(player)` 将物理运算交由玩家客户端处理，实现 0ms 延迟物理并向服务器广播。
  • NPC 与死亡尸体所有权：对于阵亡尸体或 NPC，必须调用 `SetNetworkOwner(nil)` 让服务器权威计算物理，防止客户端外挂劫持或坐标脱节。
  • 网络带宽节流：剧烈翻滚的布娃娃会生成高额网络封包，在角速度衰减至 0.1 rad/s 时应允许物理部件自动进入休眠（Sleep）。
  • 防瞬移同步时序：切勿在关闭 Motor6D 的同一帧内直接重置网络所有权，应留出至少 1 个服务端 Tick 缓冲。

4. 起身混合 (Get-Up Blending) 与状态平滑恢复

从翻滚倒地状态平滑恢复至正常站立行走姿态：

  • 地表倾角探测：在重新激活 Motor6D 之前，从 Torso 向下发射射线测量法线，将 HumanoidRootPart 的 CFrame 贴合地表坡度。
  • 杜绝原地瞬移拉扯：角色跌落过程中 RootPart 若滞留在半空中，重新开启关节会导致角色瞬间被吸回空中。必须在开启前将 RootPart 坐标与 Torso 强制对齐。
  • 起身动作过渡插值：播放专属起身动画，在 0.3 秒的混合窗口内渐进式恢复骨骼关节约束。
  • 免控霸体保护：起身动作期间赋予 0.5 秒短暂霸体，避免玩家陷入被连续击退倒地的恶性循环。

5. 移动端性能优化与生产发布规范

确保低配手机在多角色物理碰撞下维持 60 FPS 的准则：

  • 严格限制物理约束数量：仅在躯干、颈部、肩部与髋部等大关节放置 BallSocket，帽子、披风等饰品保持静态。
  • 充分利用物理引擎休眠：静止在地面上的布娃娃会自动进入休眠状态，将 CPU 占用直接降至 0。
  • 死亡垃圾回收：角色死亡后设置 10 秒倒计时，彻底销毁所有物理约束与 Attachment 释放内存。
  • MicroProfiler 性能审查：通过 Ctrl+F6 监控 `physics::step` 的开销，确保单帧物理求解耗时小于 3ms。

Frequently Asked Questions

为什么我的布娃娃角色会突然飞天或遁地穿模？

绝大多数是由于四肢部件相互重叠导致的自碰撞反冲（Self-Collision）。请为相邻肢体添加 NoCollisionConstraint，并将 HumanoidRootPart 的 CanCollide 设为 false。

布娃娃物理应该在客户端还是服务端计算？

操作中的活体玩家使用 `SetNetworkOwner(player)` 在本地客户端计算以保证平滑；死亡后的尸体与 NPC 必须使用 `SetNetworkOwner(nil)` 在服务端计算以确保多端同步。

角色起身时为什么会瞬间瞬移回最初摔倒的位置？

因为摔倒过程中 HumanoidRootPart 未跟随躯干移动。重新开启 Motor6D 前，必须先将 HumanoidRootPart 的坐标同步至当前 Torso 的实际物理位置。

BallSocketConstraint 的 TwistLimits 为什么不可或缺？

若无 TwistLimits，手肘与膝盖会沿着肢体长轴像开瓶器一样发生 360 度怪异自旋，严重破坏人体骨骼正常外观。
