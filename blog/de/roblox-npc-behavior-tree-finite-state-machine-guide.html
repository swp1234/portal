Belastbare und intelligente Gegner in Roblox zu erschaffen erfordert eine saubere Architektur. Einfache Skripte mit unzähligen if-else-Verzweigungen führen schnell zu Server-Lags, Wegfindungsfehlern und unspielbaren Frameraten.

Professionelle Roblox-Entwickler kombinieren Finite State Machines (FSM) für übergeordnete Zustände und Behavior Trees für reaktive Unterentscheidungen. Dieser Leitfaden erklärt Blackboard-Systeme, Sichtkegel-Raycasting und Server-LOD-Ticks.

1. Finite State Machines (FSM) vs. Behavior Trees (BT)

Architekturmuster je nach Gegnerkomplexität:

  • Finite State Machines (FSM): Perfekt für klare Abläufe: Patrouille, Verfolgung, Angriff. Jeder Zustand besitzt saubere Enter-, Update- und Exit-Methoden.
  • Behavior Trees (BT): Ideal für anspruchsvolle Bosse mit Deckungssuche, Waffenwechseln und Notfall-Heilung.
  • Hybride Architektur: FSM für Makrozustände (Kampf vs. Erkundung) und Behavior Trees für Mikrotaktiken.

2. Blackboard-Muster und Sensorische Wahrnehmung

Räumliche Intelligenz ohne Serverüberlastung:

  • Das Blackboard: Zentrale Tabelle für NPC-Wissen (Ziel, letzte Sichtung, Alarmstufe).
  • Sichtkegel (FOV) & Raycast: Kombination aus Vektor-Skalarprodukt (110° Blickfeld) und Raycasting gegen Wände.
  • Raycast-Budgetierung: Sensorabfragen gestaffelt alle 0,2 bis 0,4 Sekunden ausführen statt jeden Frame.

3. Production Implementation Architecture

ServerScriptService.NPCFramework.StateMachine
-- Modular Finite State Machine for Roblox NPC
local StateMachine = {}
StateMachine.__index = StateMachine

function StateMachine.new(npcInstance, states, initialState)
    local self = setmetatable({}, StateMachine)
    self.NPC = npcInstance
    self.States = states
    self.CurrentState = nil
    self.Blackboard = {
        Target = nil,
        LastSeenPos = nil,
        Health = 100,
        PatrolPoints = {}
    }

    self:ChangeState(initialState)
    return self
end

function StateMachine:ChangeState(newStateName)
    if self.CurrentState and self.States[self.CurrentState].Exit then
        self.States[self.CurrentState]:Exit(self.NPC, self.Blackboard)
    end

    self.CurrentState = newStateName
    if self.States[newStateName] and self.States[newStateName].Enter then
        self.States[newStateName]:Enter(self.NPC, self.Blackboard)
    end
end

function StateMachine:Update(dt)
    if self.CurrentState and self.States[self.CurrentState].Update then
        local nextState = self.States[self.CurrentState]:Update(self.NPC, self.Blackboard, dt)
        if nextState and nextState ~= self.CurrentState then
            self:ChangeState(nextState)
        end
    end
end

return StateMachine

4. Behavior Tree Knoten: Selektoren, Sequenzen & Dekoratoren

Strukturierte Prioritätenlogik:

  • Selector-Knoten (?): Führt Kinder aus, bis eines erfolgreich ist (Angriff -> Verfolgung -> Patrouille).
  • Sequence-Knoten (&): Führt Schritte nacheinander aus; bricht bei Fehler ab (Annähern -> Ausholen -> Schaden).
  • Decorator-Knoten: Modifizieren Ergebnisse mit Cooldowns oder Schleifen.

5. Server-Skalierung: KI-LOD und Pooling

Konstante 60 FPS bei über 100 aktiven Mobs:

  • KI-LOD: 10Hz-Prüfung in Spielernähe, 1Hz in der Ferne und Deaktivierung außerhalb von 500 Studs.
  • Client-seitige Glättung: Server berechnet Wegpunkte, Client animiert die Bewegung flüssig.
  • Object-Pooling: Wiederverwendung existierender Modelle statt ständigem Erstellen und Löschen.

Frequently Asked Questions

Warum laggt der Server bei 30 NPCs?

Weil ungedrosselte Raycasts und Pathfinding-Aufrufe jeden Frame die Server-CPU blockieren. Führen Sie KI-LOD ein.

Welchen Vorteil bieten Behavior Trees gegenüber FSMs?

Sie ermöglichen flexible Rückfallpläne und lassen sich modular erweitern, ohne komplexe Übergangsnetze umschreiben zu müssen.

Wie verhindert man, dass NPCs durch Wände sehen?

Mittels Raycast vom Kopf des NPCs zur Spielfigur unter Ausschluss transparenter Teile.

Darf der Client die KI steuern?

Nein, Kernentscheidungen müssen auf dem Server liegen, um Cheats zu verhindern. Der Client übernimmt nur optische Interpolation.
