로블록스에서 광활한 오픈월드를 제작하려면 엄격한 메모리 관리가 필수적입니다. 복잡한 지형과 고폴리곤 에셋, 다양한 상호작용 오브젝트가 맵에 가득 차면, 클라이언트가 모든 워크스페이스를 한 번에 불러오다 저사양 기기에서 치명적인 렉과 크래시를 유발합니다.

로블록스 StreamingEnabled는 플레이어의 거리와 클라이언트 메모리 부하에 맞춰 3D 공간 청크를 동적으로 스트리밍합니다. 정밀한 스트리밍 반경 설정, ModelStreamingMode 적용, 비동기 Luau 인스턴스 참조 패턴을 결합하면 저가형 스마트폰에서도 콘솔급 대작 게임을 쾌적하게 구동할 수 있습니다.

1. StreamingEnabled 핵심 원리 및 공간 청크 아키텍처

서버가 맵 데이터를 분할하고 동적으로 클라이언트에 전송하는 구조:

  • 공간 분할(64x64 스터드 청크): 워크스페이스를 입체 격자 단위로 분할하여 플레이어 주변 구역의 에셋만 네트워크를 통해 전송합니다.
  • StreamingTargetRadius vs. StreamingMinRadius: TargetRadius는 최대 시야 반경(예: 1024 스터드)을 정의하며, MinRadius는 아바타 주변의 즉각적인 충돌 판정을 보장(예: 128 스터드)합니다.
  • 기회주의적 언로드(Opportunistic Stream-Out): 저사양 모바일 기기의 메모리가 한계에 도달하면 접속을 끊지 않고 원거리 청크를 메모리에서 자동으로 제거합니다.

2. ModelStreamingMode: Atomic, Persistent, Nonatomic

오브젝트 파손을 방지하는 모델 스트리밍 모드 설정법:

  • Atomic: 모델 내부의 모든 부품이 단일 프레임에 동시에 로드됩니다. 부품이 순차적으로 로드될 경우 물리 엔진이 깨지는 차량, 엘리베이터, 기계 장치에 필수적입니다.
  • Persistent: 거리나 기기 메모리에 상관없이 접속 시 즉시 로드되고 절대 언로드되지 않습니다. 메인 로비나 핵심 스폰 지점에만 제한적으로 사용합니다.
  • PersistentPerPlayer: 서버 코드를 통해 특정 플레이어의 개인 하우징이나 소환된 차량만을 동적으로 영구 유지합니다.
  • Nonatomic (기본값): 거리 조건에 따라 부품 단위로 유연하게 로드 및 언로드되며, 정적 배경 건물과 울창한 숲에 가장 적합합니다.
ReplicatedStorage.Common.StreamHelper
-- 안전한 StreamingEnabled 인스턴스 비동기 대기 모듈
local StreamHelper = {}
local TIMEOUT_DEFAULT = 8

function StreamHelper.WaitForChildAsync(parent, childName, timeout)
    local targetTimeout = timeout or TIMEOUT_DEFAULT
    local child = parent:FindFirstChild(childName)
    if child then return child end

    local thread = coroutine.running()
    local conn

    local timer = task.delay(targetTimeout, function()
        if conn then conn:Disconnect() end
        task.spawn(thread, nil)
    end)

    conn = parent.ChildAdded:Connect(function(newChild)
        if newChild.Name == childName then
            conn:Disconnect()
            task.cancel(timer)
            task.spawn(thread, newChild)
        end
    end)

    local result = coroutine.yield()
    if not result then
        warn(string.format("[StreamHelper] Timed out waiting for '%s' in %s", childName, parent:GetFullName()))
    end
    return result
end

return StreamHelper

3. 안전한 비동기 Luau 패턴: 무한 대기 경고 방지

원거리 오브젝트 참조 시 발생하는 레이스 컨디션 해결책:

  • WaitForChild의 함정: 원거리에 있어 아직 스트리밍되지 않은 객체를 타임아웃 없이 workspace:WaitForChild("Boss")로 호출하면 영구 정지 상태에 빠집니다.
  • 비동기 스트림 대기 모듈: 타임아웃과 재시도 로직이 포함된 안전한 래퍼 함수를 사용하여 객체가 나타날 때까지 비동기 코루틴으로 처리합니다.
  • 언로드 시 리소스 해제: 원거리로 이동해 모델이 언로드될 때 AncestryChanged 이벤트를 감지하여 로컬 이벤트 리스너를 정리하고 메모리 누수를 방지합니다.

4. 모바일 기기 메모리 예산 관리 (400MB 이하)

보급형 스마트폰에서 강제 종료를 방지하는 최적화 기법:

  • 텍스처 해상도 제한: 핵심 아이템 외의 일반 텍스처는 512x512 이하로 압축하고 아틀라스 텍스처 시트로 통합합니다.
  • StreamingPauseMode 설정: 초고속 이동 중 지형이 미처 스트리밍되지 못할 때 캐릭터를 잠시 일시 정지시켜 맵 아래 허공으로 추락하는 현상을 방지합니다.
  • 개발자 콘솔(F9) 메모리 진단: GraphicsParts, Textures, Sounds 카테고리를 실시간 점검하여 모바일 기준 총 메모리 사용량을 350MB 이하로 유지합니다.

5. 거리 기반 LOD(Level of Detail) 및 임포스터 메시

폴리곤 과부하 없이 광활한 지평선과 도시 경관을 연출하는 방법:

  • 원거리 저폴리곤 교체: 150스터드 이상 떨어진 배경은 50트라이앵글 이하의 단순한 실루엣 메시로 대체하여 렌더링 비용을 90% 이상 절감합니다.
  • 오클루전 컬링(시야 차단 설계): 협곡, 건물 외벽, 실내 복도를 전략적으로 배치하여 시야 밖의 거대한 맵 청크가 렌더링 파이프라인에서 자동 제외되도록 설계합니다.
  • 메시 인스턴싱 재사용: 동일한 MeshPart ID를 맵 전체에 재활용하여 모바일 GPU 드로우 콜을 획기적으로 줄입니다.

Frequently Asked Questions

로블록스 StreamingEnabled의 가장 큰 장점은 무엇인가요?

플레이어 주변의 3D 공간 청크만 선별 로드하고 원거리 오브젝트를 메모리에서 제거함으로써, 저사양 스마트폰에서도 거대한 오픈월드를 램 부족 크래시 없이 원활히 플레이할 수 있습니다.

ModelStreamingMode.Atomic은 언제 사용해야 하나요?

차량, 복잡한 문, 기계 장치처럼 모델의 부품들이 단일 묶음으로 한 번에 로드되지 않으면 물리 연산이 파손되는 객체에 사용합니다.

workspace:WaitForChild() 호출 시 무한 대기 경고가 뜨는 이유는 무엇인가요?

StreamingEnabled 환경에서는 플레이어와 멀리 떨어진 오브젝트가 클라이언트에 존재하지 않으므로, 타임아웃 없이 무한 대기하면 스크립트 실행이 영구 중단됩니다.

StreamingPauseMode는 어떤 역할을 하나요?

초고속 주행 등으로 지형이 제때 로드되지 못할 때 캐릭터를 일시적으로 멈추어 허공으로 추락하는 현상을 물리적으로 방지합니다.

원거리 시야를 유지하면서 스트리밍 반경을 줄이려면 어떻게 해야 하나요?

원거리 풍경에는 최소한의 폴리곤으로 제작된 저사양 실루엣 메시나 스카이박스 배경을 배치하여 시각적 완성도와 성능을 동시에 잡을 수 있습니다.
