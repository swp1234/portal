Concevoir des ennemis captivants et crédibles dans Roblox requiert une architecture décisionnelle structurée. Entasser tous les comportements dans un script géant rempli de conditions imbriquées mène inévitablement à des bugs de trajectoire et de lourds ralentissements serveur.

Les studios professionnels s'appuient sur deux approches complémentaires : les machines à états finis (FSM) pour la gestion macroscopique et les arbres de comportement pour les tactiques réactives. Ce guide aborde les blackboards, le raycasting de vision et la régulation des ticks par LOD.

1. Machines à États Finis (FSM) vs Arbres de Comportement (BT)

Choisir le bon modèle en fonction du type d'ennemi :

  • Machines à États Finis (FSM) : Idéales pour des cycles clairs : Patrouille, Alerte, Poursuite, Attaque. Chaque état possède ses méthodes Enter, Update et Exit.
  • Arbres de Comportement (BT) : Parfaits pour les boss complexes nécessitant mise à couvert, choix d'armes et repli tactique.
  • Architecture Hybride : FSM pour le contexte global et Arbres de Comportement pour résoudre les micro-décisions de combat.

2. Le Motif Blackboard et la Perception Sensorielle

Calculer la conscience spatiale sans surcharger le processeur :

  • Le Blackboard : Dictionnaire de données centralisé stockant la mémoire du PNJ (cible actuelle, dernière coordonnée vue, niveau d'alerte).
  • Cône de Vue et Raycasting : Produit scalaire pour valider un angle de 110° associé à un raycast vérifiant l'absence d'obstacle.
  • Budget Raycast : Échelonner les calculs toutes les 0,2 à 0,4 secondes plutôt qu'à chaque frame.

3. Production Implementation Architecture

ServerScriptService.NPCFramework.StateMachine
-- Modular Finite State Machine for Roblox NPC
local StateMachine = {}
StateMachine.__index = StateMachine

function StateMachine.new(npcInstance, states, initialState)
    local self = setmetatable({}, StateMachine)
    self.NPC = npcInstance
    self.States = states
    self.CurrentState = nil
    self.Blackboard = {
        Target = nil,
        LastSeenPos = nil,
        Health = 100,
        PatrolPoints = {}
    }
    
    self:ChangeState(initialState)
    return self
end

function StateMachine:ChangeState(newStateName)
    if self.CurrentState and self.States[self.CurrentState].Exit then
        self.States[self.CurrentState]:Exit(self.NPC, self.Blackboard)
    end
    
    self.CurrentState = newStateName
    if self.States[newStateName] and self.States[newStateName].Enter then
        self.States[newStateName]:Enter(self.NPC, self.Blackboard)
    end
end

function StateMachine:Update(dt)
    if self.CurrentState and self.States[self.CurrentState].Update then
        local nextState = self.States[self.CurrentState]:Update(self.NPC, self.Blackboard, dt)
        if nextState and nextState ~= self.CurrentState then
            self:ChangeState(nextState)
        end
    end
end

return StateMachine

4. Nœuds d'Arbres de Comportement : Sélecteurs et Séquences

Hiérarchisation des priorités tactiques :

  • Nœuds Sélecteurs (?) : Testent les branches de gauche à droite jusqu'au premier succès (Attaquer -> Poursuivre -> Patrouiller).
  • Nœuds Séquences (&) : Exécutent les étapes dans l'ordre (S'approcher -> Armer le coup -> Blesser).
  • Nœuds Décorateurs : Altèrent le retour avec des délais ou des boucles conditionnelles.

5. Scalabilité Serveur : LOD d'IA et Object Pooling

Conserver 60 FPS constants avec plus de 100 monstres en jeu :

  • LOD d'Intelligence Artificielle : Actualisation à 10Hz près du joueur, 1Hz à distance et mise en sommeil au-delà de 500 studs.
  • Lissage Côté Client : Le serveur dicte les waypoints, le client interpole les mouvements et l'animation de marche.
  • Object Pooling : Réutilisation de modèles existants via transparence et CFrame pour éviter les allocations mémoire répétées.

Frequently Asked Questions

Pourquoi 30 PNJ suffisent-ils à ralentir un serveur ?

Parce que répéter les raycasts et les calculs de pathfinding à 60 FPS sature le CPU. Appliquez un LOD d'IA pour espacer les requêtes.

Quel est l'avantage des Arbres de Comportement face aux FSM ?

Ils permettent d'insérer de nouveaux comportements modulaires sans reconstruire l'ensemble des liens de transition.

Comment empêcher les monstres de voir à travers les murs ?

En lançant un raycast de la tête du PNJ vers le torse du joueur en vérifiant l'absence d'obstacle intermédiaire.

Peut-on exécuter l'IA côté client ?

Non, les décisions capitales et les dégâts doivent demeurer sur le serveur afin d'éviter toute triche.
