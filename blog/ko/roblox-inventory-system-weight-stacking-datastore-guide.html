로블록스 인벤토리 아키텍처: 그리드 슬롯, 무게 버짓 & 서버 권한 스택 시스템

시스템 아키텍처 원칙: 클라이언트의 아이템 수량, 슬롯 좌표, 무게 계산을 결코 신뢰하지 마십시오. 아이템 드래그부터 포션 분할까지 모든 인벤토리 상호작용은 서버의 원자적 트랜잭션으로 처리되고, 낙관적 UI 업데이트를 통해 렉 없는 조작감을 제공해야 합니다.

인벤토리 시스템은 RPG, 서바이벌, 익스트랙션 슈터 등 로블록스 핵심 장르의 기반입니다. 설계를 소홀히 하면 복사 버그, 단축키 동기화 오류, 모바일 드래그 앤 드롭 렉으로 인해 게임 경제가 붕괴됩니다.

서버 권한 상태 머신, 모듈형 스택 제한, 복합 아이템 딕셔너리 구조, 그리고 ProfileService 기반의 세션 락 영속 저장을 구축하면 동시접속 수천 명에서도 안전하고 견고한 인벤토리를 완성할 수 있습니다.

1. 인벤토리 설계 모델: 고정 슬롯 vs. 공간 그리드 vs. 무게 제한

게임 장르와 루프에 최적화된 인벤토리 구조 선택:

  • 고정 슬롯 아키텍처: 클래식 MMO/핫바 형태로 고정된 인덱스 배열(예: 20슬롯)을 사용합니다. O(1) 검색과 직관적인 데이터 직렬화가 가능하여 빠른 액션 게임에 적합합니다.
  • 공간 테트리스 그리드: 디아블로/타르코프 스타일의 다중 셀 배치(예: 소총 2x5칸). 배치 시 2D 비트마스크나 충돌 검증 배열 계산이 필요합니다.
  • 무게 및 과적(Encumbrance) 버짓: 아이템마다 질량 값을 부여해 총합을 한도와 비교합니다. 한도 초과 시 단계별 이동속도 감소 및 스태미나 소모 페널티를 적용합니다.

2. 서버 권한 상태 검증 & 낙관적 클라이언트 UI

보안 취약점 없이 0초 체감 반응속도를 구현하는 파이프라인:

  • 낙관적 UI 예측(Optimistic UI): 아이템 드롭 시 클라이언트 화면에서 즉시 슬롯 아이콘을 이동시키고 사운드를 재생해 서버 왕복 핑을 기다리지 않습니다.
  • 서버 유효성 검증 & 뮤텍스 락: 서버는 아이템 소유권, 슬롯 경계, 무게 한도, 쿨다운을 원자적으로 검증한 후 상태를 확정합니다.
  • 조정(Reconciliation) 및 롤백: 유효하지 않은 이동 요청이나 치트 시도가 발생하면 즉시 에러 패킷을 보내 이전 정상 좌표로 아이콘을 원상 복구합니다.

3. 복합 아이템 데이터 구조 & 스택 직렬화 최적화

가변/불변 속성을 깔끔하게 분리하는 Luau 설계 기법:

  • 기본 템플릿과 고유 인스턴스 분리: 이름, 아이콘, 최대 스택, 기본 무게는 ReplicatedStorage 공용 DB에 두고, 고유 UUID, 내구도, 강화 옵션만 플레이어 상태에 저장합니다.
  • 스택 병합 및 분할 공식: 병합 시 대상 슬롯의 남은 용량 math.min(maxStack - target.Count, source.Count)을 계산해 원자적으로 수량을 이전합니다.
  • DataStore 직렬화 압축: 빈 슬롯과 기본값은 저장 시 제외하여 데이터 페이로드 용량을 최소화하고 4MB 세이브 제한을 안전하게 준수합니다.
ServerScriptService.Inventory.InventoryManager
-- 서버 권한 인벤토리 트랜잭션 핸들러
local InventoryManager = {}
InventoryManager.__index = InventoryManager

local ItemDatabase = require(game.ReplicatedStorage.ItemDatabase)

function InventoryManager.new(player, maxSlots, maxWeight)
    local self = setmetatable({}, InventoryManager)
    self.Player = player
    self.MaxSlots = maxSlots or 30
    self.MaxWeight = maxWeight or 100
    self.Slots = table.create(self.MaxSlots, false)
    self.CurrentWeight = 0
    self.IsLocked = false
    return self
end

function InventoryManager:AddItem(itemId, amount)
    if self.IsLocked then return false, "INVENTORY_LOCKED" end
    local itemData = ItemDatabase[itemId]
    if not itemData then return false, "INVALID_ITEM" end
    
    local addedWeight = itemData.Weight * amount
    if self.CurrentWeight + addedWeight > self.MaxWeight then
        return false, "OVER_ENCUMBERED"
    end
    
    -- 1. 기존 스택 병합 시도
    for slotIndex = 1, self.MaxSlots do
        local slot = self.Slots[slotIndex]
        if slot and slot.Id == itemId and slot.Count < itemData.MaxStack then
            local space = itemData.MaxStack - slot.Count
            local toAdd = math.min(space, amount)
            slot.Count = slot.Count + toAdd
            amount = amount - toAdd
            self.CurrentWeight = self.CurrentWeight + (itemData.Weight * toAdd)
            if amount <= 0 then return true end
        end
    end
    
    -- 2. 빈 슬롯에 신규 배치
    for slotIndex = 1, self.MaxSlots do
        if not self.Slots[slotIndex] then
            self.Slots[slotIndex] = {
                UUID = game:GetService("HttpService"):GenerateGUID(false),
                Id = itemId,
                Count = amount,
                Durability = itemData.MaxDurability
            }
            self.CurrentWeight = self.CurrentWeight + (itemData.Weight * amount)
            return true
        end
    end
    return false, "INVENTORY_FULL"
end

return InventoryManager

4. 복사 버그 방지 & 트랜잭션 락 보안 (ProfileService)

강제 종료 복사 버그, 아이템 드롭 경쟁, 거래 악용 차단:

  • MemoryStore 세션 락: 아이템 드롭이나 거래 시 임시 분산 락 키를 획득하여 동시 접근으로 인한 이중 사용(Double-spend)을 차단합니다.
  • 원자적 거래 커밋: 플레이어 간 교환 시 단일 서버 프레임에서 동시 교환하거나, 예기치 않은 연결 끊김 시 양쪽 모두 즉시 롤백합니다.
  • 요청 빈도 제한(Rate Limiting): 아이템 이동 요청 간 100ms 이상의 최소 쿨다운을 적용해 패킷 플러딩 공격과 상태 꼬임을 방지합니다.

5. 모바일 친화적 드래그 앤 드롭 & 터치 스케일링 UX

스마트폰, 태블릿, 콘솔 전 환경에서 쾌적한 인벤토리 조작감:

  • 최소 44px 터치 타깃 보장: 화면 해상도에 맞게 UIScale을 동적 조정하여 모바일 화면에서도 오클릭 없는 쾌적한 터치 영역을 유지합니다.
  • 길게 누르기(Long Press) 원형 메뉴: 우클릭이 없는 터치 환경에서는 길게 누름 제스처로 사용, 분할, 버리기, 상세 정보 원형 메뉴를 호출합니다.
  • 햅틱 및 오디오 피드백: HapticService를 연동해 아이템 슬롯 장착 시 기기 미세 진동과 스냅 사운드를 출력해 완성도 높은 손맛을 제공합니다.

Frequently Asked Questions

로블록스 인벤토리 로직을 반드시 서버에서 처리해야 하는 이유는 무엇인가요?

클라이언트에서 아이템 이전을 계산하면 해커가 가짜 아이템을 주입하거나 복사 버그를 일으킬 수 있습니다. 서버에서 검증해야 모든 경제 데이터의 무결성이 보장됩니다.

낙관적 UI(Optimistic UI)는 어떻게 인벤토리 조작 렉을 없애나요?

유저가 드래그를 놓는 즉시 로컬 화면에서 아이콘을 옮겨 0ms 체감을 주고, 서버 승인이 오면 확정, 거절 시에만 원래 위치로 복귀시킵니다.

세션 락(Session Locking)이란 무엇이며 왜 필수인가요?

한 시점에 오직 하나의 서버만 플레이어의 저장 데이터를 수정할 수 있도록 잠그는 기법으로, 다중 접속이나 강제 종료를 이용한 복사 버그를 원천 봉쇄합니다.

모바일 화면에서 드래그 조작 튐 현상을 어떻게 방지하나요?

터치 이동 시 가벼운 복제본 아이콘만 손가락 좌표를 따라다니게 하고, 실제 슬롯 안착 판정은 손가락을 뗐을 때(TouchEnded) 1회만 계산합니다.
