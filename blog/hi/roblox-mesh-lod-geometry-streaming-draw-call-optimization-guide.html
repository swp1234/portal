रोब्लॉक्स में बड़े खुले संसार बनाते समय मोबाइल फोन पर अत्यधिक लैग और क्रैश की समस्या आम है।

व्यवस्थित Level of Detail (LOD) पाइपलाइन बनाकर उच्च ग्राफिक्स गुणवत्ता के साथ कम क्षमता वाले फोन पर भी 60 FPS बनाए रखा जा सकता है।

1. जीपीयूँ बाधाएं: ड्रा कॉल और पॉलीगॉन भार

हार्डवेयर सीमाओं का तकनीकी विश्लेषण:

  • ड्रा कॉल का बोझ: 1,500 से अधिक ड्रा कॉल मोबाइल प्रोसेसर को धीमा कर देते हैं।
  • वर्टेक्स की बर्बादी: दूर के पेड़ों पर हजारों पॉलीगॉन बनाना शक्ति की बर्बादी है।
  • बार-बार टेक्सचर बदलना: ग्राफिक्स पाइपलाइन को रोक देता है।
  • मोबाइल ओवरहीटिंग: ज्यादा भार से फोन गर्म होकर गति धीमी कर देता है।

2. RenderFidelity और रोब्लॉक्स का अपना LOD सिस्टम

स्वचालित मेश सरलीकरण का सही उपयोग:

  • `RenderFidelity.Precise`: पूरी ज्यामिति रखता है; केवल पास की वस्तुओं के लिए उपयोग करें।
  • `RenderFidelity.Performance`: दूरी के अनुसार स्वचालित रूप से 4 स्तर बनाता है।
  • `CollisionFidelity.Box`: सजावटी वस्तुओं के टकराव बॉक्स को सरल बनाना।
  • स्वचालित इंस्टेंसिंग: एक जैसे मेश को एक साथ रेंडर करना।
लुआउ कस्टम दूरी आधारित LOD और इम्पोस्टर स्क्रिप्ट
--!strict
local RunService = game:GetService("RunService")
local Workspace = game:GetService("Workspace")

local LODManager = {}
type LODModel = { HighDetail: Model, LowDetail: Model, Impostor: BillboardGui, Position: Vector3, CurrentTier: number }
local registeredLODs: {LODModel} = {}

function LODManager.Register(high: Model, low: Model, impostor: BillboardGui, centerPos: Vector3)
    table.insert(registeredLODs, { HighDetail = high, LowDetail = low, Impostor = impostor, Position = centerPos, CurrentTier = 1 })
    low.Parent = nil
    impostor.Enabled = false
end

local frameCounter = 0
RunService.Heartbeat:Connect(function()
    frameCounter += 1
    if frameCounter % 6 ~= 0 then return end
    local camera = Workspace.CurrentCamera
    if not camera then return end
    local camPos = camera.CFrame.Position
    for _, lod in ipairs(registeredLODs) do
        local offset = lod.Position - camPos
        local distSq = offset.X * offset.X + offset.Y * offset.Y + offset.Z * offset.Z
        local newTier = distSq > 640000 and 4 or (distSq > 122500 and 3 or (distSq > 14400 and 2 or 1))
        if newTier ~= lod.CurrentTier then
            lod.CurrentTier = newTier
            lod.HighDetail.Parent = (newTier == 1) and Workspace or nil
            lod.LowDetail.Parent = (newTier == 2) and Workspace or nil
            lod.Impostor.Enabled = (newTier == 3)
        end
    end
end)

return LODManager

3. 2D बिलबोर्ड इम्पोस्टर्स

दूर की 3D वस्तुओं को 2D फ्लैट इमेज से बदलना:

  • इम्पोस्टर तकनीक: 300 स्टड्स से दूर जटिल भवन को 2D टेक्सचर से बदलना।
  • पॉलीगॉन में भारी बचत: लाखों वर्टेक्स को केवल सैकड़ों में समेटना।
  • कम ड्रा कॉल: एक ही इमेज शीट से कई वस्तुओं को प्रदर्शित करना।
  • सॉफ्ट ट्रांज़िशन: अचानक बदलने से रोकने के लिए हल्का फेड इफेक्ट।

4. StreamingEnabled और मेमोरी प्रबंधन

बड़े नक्शों को फोन की मेमोरी में सुरक्षित लोड करना:

  • कम StreamingMinRadius: फोन क्रैश होने से बचाना।
  • `ModelStreamingMode.Atomic`: वाहनों को एक पूरे हिस्से के रूप में लोड करना।
  • `ModelStreamingMode.Persistent`: मुख्य इमारतों को हमेशा लोड रखना।
  • मेमोरी अलर्ट पर रेंडर दूरी को कम करना।

5. मोबाइल प्रोडक्शन चेकलिस्ट

सुचारू गेमप्ले के नियम:

  • छोटी वस्तुओं के टेक्सचर को एक 1024x1024 शीट में जोड़ना।
  • घास और पत्थरों पर CastShadow बंद करना।
  • MicroProfiler में फ्रेम समय 16.6ms से कम रखना।
  • सस्ते फोन पर नियमित परीक्षण करना।
