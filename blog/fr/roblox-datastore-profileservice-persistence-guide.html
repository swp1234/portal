Rien ne fait fuir les joueurs et ne détruit les notes d'un jeu Roblox plus vite que la perte d'inventaire. Lorsque les serveurs redémarrent ou que les joueurs changent de serveur à répétition, l'utilisation naïve de `SetAsync` génère des écrasements irrémédiables.

En 2026, la création de jeux commerciaux exige une persistance de niveau professionnel. Ce guide détaille le mécanisme de Session Locking, l'obligation d'utiliser `UpdateAsync` et la façon dont ProfileService élimine tout risque de corruption.

Règle d'or Roblox: N'utilisez jamais SetAsync pour les données de joueurs en direct. Utilisez toujours UpdateAsync avec verrouillage de session.

1. Comprendre la Perte de Données: Conditions de Concurrence

Pourquoi les architectures distribuées effacent parfois les inventaires:

  • Concurrence Multi-Serveurs: Si un joueur quitte le Serveur A et rejoint le Serveur B instantanément, le Serveur B risque de charger des données obsolètes avant la sauvegarde du Serveur A.
  • Pannes Réseau sans pcall: Un échec HTTP 500 non intercepté stoppe le script et abandonne la sauvegarde.
  • Dépassement des Quotas: Dépasser les limites d'écriture par minute entraîne le rejet silencieux des requêtes.

2. Fonctionnement du Session Locking avec ProfileService

Garantir qu'un seul serveur actif possède le droit d'écriture:

  • Attribution du Verrou: Le Serveur A inscrit son JobId dans les métadonnées pour sécuriser la session.
  • Blocage des Sessions Parallèles: Le Serveur B patiente tant que le Serveur A n'a pas formellement libéré le profil.
  • Sauvegarde Automatique: ProfileService enregistre les modifications toutes les 30 secondes en tâche de fond.

3. Migrations de Données et Évolution du Schéma

Ajouter de nouvelles fonctionnalités sans réinitialiser les comptes:

  • Modèle Immuable: Déclarez un tableau modèle contenant toutes les valeurs par défaut.
  • Fonction Reconcile: Profile:Reconcile() ajoute automatiquement les nouvelles clés sans modifier les anciennes.
  • Numéro de Version: Utilisez une variable DataVersion pour exécuter des scripts de refonte de structure.

4. Script de Production: Implémentation ProfileService

Un script complet et sécurisé prêt pour la production:

ServerScriptService.DataManager (ProfileService)
local Players = game:GetService("Players")
local ProfileService = require(script.ProfileService)

local ProfileTemplate = {
    Coins = 100,
    Gems = 0,
    Inventory = {},
    LogInTimes = 0,
}

local ProfileStore = ProfileService.GetProfileStore(
    "PlayerData_v1.0",
    ProfileTemplate
)

local Profiles = {}

local function OnPlayerAdded(player)
    local profile = ProfileStore:LoadProfileAsync("Player_" .. player.UserId)
    if profile ~= nil then
        profile:AddUserId(player.UserId)
        profile:Reconcile()
        profile:ListenToRelease(function()
            Profiles[player] = nil
            player:Kick("Session ouverte ailleurs. Veuillez vous reconnecter.")
        end)
        if player:IsDescendantOf(Players) == true then
            Profiles[player] = profile
        else
            profile:Release()
        end
    else
        player:Kick("Impossible de charger votre sauvegarde.")
    end
end

local function OnPlayerRemoving(player)
    local profile = Profiles[player]
    if profile ~= nil then
        profile:Release()
    end
end

Players.PlayerAdded:Connect(OnPlayerAdded)
Players.PlayerRemoving:Connect(OnPlayerRemoving)

Fonctionnement: Charge avec Session Lock, complète le schéma avec Reconcile et libère le verrou proprement au départ du joueur.

5. Optimisation et Tolérance aux Pannes

Bonnes pratiques pour les environnements en direct:

  • Délai BindToClose: game:BindToClose accorde jusqu'à 30 secondes pour enregistrer les profils avant l'extinction du serveur.
  • Mode Mock dans Studio: Utilisez ProfileStore.Mock pour tester sans impacter les quotas réels.
  • Compression des Données: Sérialisez les gros inventaires pour respecter la limite de 4 Mo par clé.

Foire Aux Questions (Roblox DataStores & ProfileService)

Pourquoi SetAsync est-il dangereux?

SetAsync écrase aveuglément les données distantes. Lors d'un changement rapide de serveur, une sauvegarde lente peut effacer les gains d'une sauvegarde récente.

Qu'est-ce que le Session Locking?

C'est un verrou numérique garantissant qu'un seul serveur actif peut modifier les données du joueur à la fois, éliminant les duplications d'objets.

Quelle est la limite de stockage par clé en 2026?

Jusqu'à 4 Mo (4 194 304 caractères JSON) par clé, ce qui est largement suffisant pour de vastes inventaires RPG.

ProfileService protège-t-il contre l'arrêt inopiné du serveur?

Oui. Il s'intègre automatiquement à game:BindToClose pour tenter de sauvegarder et libérer tous les profils avant l'arrêt du serveur.
