Menciptakan musuh yang pintar di Roblox memerlukan arsitektur keputusan yang terstruktur rapi. Menulis semua perilaku dalam satu skrip penuh kondisi if-else membuat musuh sering macet dan menyebabkan lag parah pada server.

Game komersial memadukan Finite State Machines (FSM) untuk status umum dan Behavior Trees untuk taktik tempur dinamis. Panduan ini membahas pola Blackboard, raycasting sudut pandang, dan pembagian beban tick melalui sistem LOD.

1. Finite State Machines (FSM) vs Behavior Trees (BT)

Menentukan pola arsitektur yang tepat:

  • Finite State Machines (FSM): Cocok untuk tahapan aksi yang jelas: Patroli, Waspada, Mengejar, dan Menyerang dengan fungsi Enter, Update, dan Exit.
  • Behavior Trees (BT): Pilihan tepat untuk bos yang memiliki beragam reaksi seperti mencari perlindungan atau menyembuhkan diri.
  • Struktur Gabungan: FSM mengontrol status utama sementara Behavior Tree menangani keputusan taktis dalam pertempuran.

2. Pola Blackboard & Penglihatan Sensori

Memberikan kesadaran ruang tanpa membebani prosesor server:

  • Blackboard: Tabel terpusat untuk menyimpan memori NPC (target, koordinat terakhir, status amunisi).
  • Sudut Pandang & Raycasting: Dot product untuk sudut pandang 110° dan raycast untuk memastikan tidak terhalang tembok.
  • Penghematan Raycast: Jalankan pemindaian setiap 0.2 hingga 0.4 detik secara bergantian antar grup musuh.

3. Production Implementation Architecture

ServerScriptService.NPCFramework.StateMachine
-- Modular Finite State Machine for Roblox NPC
local StateMachine = {}
StateMachine.__index = StateMachine

function StateMachine.new(npcInstance, states, initialState)
    local self = setmetatable({}, StateMachine)
    self.NPC = npcInstance
    self.States = states
    self.CurrentState = nil
    self.Blackboard = {
        Target = nil,
        LastSeenPos = nil,
        Health = 100,
        PatrolPoints = {}
    }

    self:ChangeState(initialState)
    return self
end

function StateMachine:ChangeState(newStateName)
    if self.CurrentState and self.States[self.CurrentState].Exit then
        self.States[self.CurrentState]:Exit(self.NPC, self.Blackboard)
    end

    self.CurrentState = newStateName
    if self.States[newStateName] and self.States[newStateName].Enter then
        self.States[newStateName]:Enter(self.NPC, self.Blackboard)
    end
end

function StateMachine:Update(dt)
    if self.CurrentState and self.States[self.CurrentState].Update then
        local nextState = self.States[self.CurrentState]:Update(self.NPC, self.Blackboard, dt)
        if nextState and nextState ~= self.CurrentState then
            self:ChangeState(nextState)
        end
    end
end

return StateMachine

4. Node Behavior Tree: Selector dan Sequence

Menyusun hierarki prioritas tindakan:

  • Node Selector (?): Menjalankan opsi dari kiri ke kanan hingga menemukan yang berhasil (Serang -> Kejar -> Patroli).
  • Node Sequence (&): Memastikan seluruh rangkaian langkah terpenuhi (Mendekat -> Ayunkan Senjata -> Berikan Damage).
  • Node Decorator: Mengatur pengulangan atau jeda waktu antar aksi.

5. Skalabilitas Server: AI LOD & Object Pooling

Menjaga performa tetap 60 FPS meski ada lebih dari 100 musuh:

  • AI LOD: Pemindaian 10Hz saat dekat pemain, 1Hz saat jauh, dan mematikan kalkulasi pada jarak 500 stud.
  • Penghalusan Gerak di Client: Server hanya mengirimkan titik rute, sementara client menganimasikan gerakan dan rotasi.
  • Object Pooling: Menggunakan kembali model NPC yang ada alih-alih membuat dan menghapusnya berulang kali.

Frequently Asked Questions

Mengapa 30 NPC membuat server lag parah?

Karena raycast dan kalkulasi jalur yang berjalan setiap frame membebani CPU. Terapkan AI LOD untuk membagi beban.

Apa keunggulan Behavior Tree dibanding FSM?

BT memungkinkan penambahan taktik baru secara modular tanpa merombak diagram transisi yang rumit.

Bagaimana mencegah musuh melihat tembus dinding?

Gunakan raycast dari kepala NPC ke tubuh pemain untuk memastikan jalur pandang terbebas dari rintangan.

Bolehkah client mengontrol pergerakan AI?

Tidak, logika keputusan dan pemberian damage harus berada di server guna mencegah eksploitasi dan kecurangan.
