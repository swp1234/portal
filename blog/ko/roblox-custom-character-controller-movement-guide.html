DopaBrain 게임 개발 연구소 • 업데이트: 2026년 9월 • 읽는 시간: 9분
조작감 설계 황금률: 기본 Humanoid는 무거운 C++ 물리 연산이 얽혀 있는 거대 상태 머신입니다. 민첩한 파쿠르나 정밀 조작을 원한다면 캡슐 충돌체와 커스텀 바닥 감지 레이캐스트 기반의 경량 컨트롤러를 설계하세요.

개발자 인지 도구 모음

두뇌 유형 테스트 벡터 키네마틱 공간 연산력 반응속도 테스트 입력-동작 즉각성 측정 스트레스 측정 엔진 디버깅 인지 피로도 2048 퍼즐 좌표계 행렬 논리

로블록스의 기본 `Humanoid`는 소셜 캐주얼 게임에는 매우 편리하지만, 정밀한 점프 맵, 파쿠르, 고속 FPS에서는 붕 뜨는 점프(Floaty Jump), 모서리 걸림, 계단 버벅임 등 수많은 물리적 한계를 드러냅니다.

타이탄폴, 슈퍼 마리오 64, 혹은 상용 콘솔 게임 수준의 극도로 민첩하고 반응성 높은 조작감을 구현하기 위해 상위 개발자들은 기본 Humanoid 물리를 배제하고 레이캐스트와 `LinearVelocity`, 절차적 충돌체를 결합한 커스텀 캐릭터 컨트롤러를 구축합니다.

1. 기본 Humanoid의 한계와 커스텀 컨트롤러의 필요성

상용 액션 게임들이 기본 캐릭터 물리를 대체하는 핵심 이유:

  • 불안정한 바닥 충돌: 기본 휴머노이드는 내부 레이캐스트가 메시 이음새나 급경사 웨지(Wedge)를 장애물로 오인하여 덜컥거리는 현상이 자주 발생합니다.
  • 부자연스러운 점프 곡선: 키 입력 시간에 따른 가변 점프가 지원되지 않고 고정된 속도로 상승하여 점프감이 둔합니다.
  • 경직된 상태 전환: 자유낙하, 등반, 기상 등의 상태가 내부 엔진에 묶여 있어 부드러운 슬라이딩이나 벽 타기(Wall Run) 구현 시 충돌이 일어납니다.

2. 아키텍처 선택: 물리 기반(Physics) vs 키네마틱(Kinematic)

캐릭터 이동을 구현하는 두 가지 핵심 패러다임 비교:

  • 물리 기반 컨트롤러(Forces): 앵커되지 않은 캡슐에 `LinearVelocity`나 `VectorForce`를 적용합니다. 움직이는 발판이나 오브젝트 충돌에 자연스럽게 반응하지만 경사면 미끄러짐 방지 튜닝이 필요합니다.
  • 키네마틱 레이캐스트 컨트롤러(CFrame): 매 프레임 레이캐스트로 주변 지형을 스캔하고 `CFrame`을 직접 갱신합니다. 아케이드급의 정밀한 조작감을 얻을 수 있으나 발판 관성 계산을 직접 코딩해야 합니다.
  • 하이브리드 컨트롤러(상용 표준): 충돌 처리는 `LinearVelocity`로 물리 엔진에 맡기고, 지면 흡착 및 경사면 각도 계산은 하향 레이캐스트로 직접 제어하는 방식입니다.

3. 고급 액션 메커니즘: 경사면 슬라이딩, 벽 점프, 코요테 타임

매끄러운 이동 쾌감을 만드는 핵심 수학 공식:

  • 경사면 법선 벡터 투영: 바닥 법선 벡터와 수직 벡터의 내적(`normal:Dot(Vector3.yAxis)`)을 계산하여 특정 각도(예: 45도 이상) 초과 시 마찰력을 미끄러짐 가속도로 치환합니다.
  • 벽 점프 반사 벡터: 이동 방향으로 수평 레이를 쏘아 벽면 충돌을 감지하고, 벽면 법선의 반사 방향과 상승 점프력을 합성하여 튕겨 나가는 도약을 구현합니다.
  • 코요테 타임 & 점프 버퍼링: 절벽에서 벗어난 후 약 100~150ms 동안 점프 입력을 유예(코요테 타임)하고, 착지 100ms 전 입력을 기억(버퍼링)하여 점프 씹힘 현상을 완벽히 방지합니다.

4. 실전 Lua 코드: 레이캐스트 바닥 감지 및 경사면 모듈

지면 흡착 및 경사면 각도 판정을 담당하는 클라이언트 핵심 모듈:

ReplicatedStorage.Controllers.GroundSensor (상용 표준 모듈)
local Workspace = game:GetService("Workspace")

local GroundSensor = {}
GroundSensor.__index = GroundSensor

function GroundSensor.new(rootPart, characterHeight)
    local self = setmetatable({}, GroundSensor)
    self.RootPart = rootPart
    self.CheckDistance = (characterHeight / 2) + 0.8
    self.RaycastParams = RaycastParams.new()
    self.RaycastParams.FilterType = RaycastFilterType.Exclude
    self.RaycastParams.FilterDescendantsInstances = {rootPart.Parent}
    return self
end

function GroundSensor:CheckGround()
    local origin = self.RootPart.Position
    local direction = -Vector3.yAxis * self.CheckDistance
    local result = Workspace:Raycast(origin, direction, self.RaycastParams)

    if result then
        local surfaceNormal = result.Normal
        local slopeAngle = math.deg(math.acos(surfaceNormal:Dot(Vector3.yAxis)))
        local isWalkable = slopeAngle <= 50

        return {
            IsGrounded = true,
            Distance = result.Distance,
            Normal = surfaceNormal,
            SlopeAngle = slopeAngle,
            IsWalkable = isWalkable,
            Material = result.Material
        }
    end

    return {
        IsGrounded = false,
        Distance = math.huge,
        Normal = Vector3.yAxis,
        SlopeAngle = 0,
        IsWalkable = false,
        Material = Enum.Material.Air
    }
end

return GroundSensor

5. 서버 권한 검증 및 벽 뚫기(Noclip) 핵 방어

커스텀 컨트롤러의 자유도를 악용한 변조를 막는 보안 수칙:

  • 틱당 최대 이동 거리 제한: 서버에서 직전 위치와 현재 위치의 거리를 추적하여 허용 최고속도를 초과하는 텔레포트 변조를 차단합니다.
  • 구체 캐스팅(Spherecast) 벽 관통 감지: 이전 프레임 위치와 새 위치 사이에 두꺼운 구체를 스위핑하여 얇은 벽을 뚫고 지나가는 핵을 검출합니다.
  • 서버 소프트 롤백: 비정상 좌표 감지 시 즉시 튕겨내는 대신, 부드러운 위치 보간을 통해 마지막 정상 위치로 캐릭터를 회수합니다.

자주 묻는 질문 (FAQ)

커스텀 컨트롤러를 만들 때 Humanoid를 아예 삭제해야 하나요?

아닙니다. 애니메이션 재생 및 의상 렌더링을 위해 Humanoid를 유지하되, `PlatformStand = true` 또는 상태를 Physics로 고정하여 기본 이동 물리만 무력화하는 방식을 권장합니다.

움직이는 발판 위에서 캐릭터가 미끄러지지 않게 하려면 어떻게 하나요?

하향 레이캐스트로 감지된 발판 파트의 델타 이동 속도를 매 프레임 캐릭터의 이동 벡터에 합산해 주면 자연스럽게 발판에 실려 이동합니다.

경사면을 내려갈 때 캐릭터가 덜덜 떨리는 이유는 무엇인가요?

착지 상태와 공중 상태가 매 프레임 번갈아 토글되기 때문입니다. 바닥에서 떨어질 때는 더 큰 거리를 요구하는 히스테리시스(Hysteresis) 완충값을 설정해야 합니다.

모바일 가상 조이스틱과 게임패드 입력도 지원되나요?

네. 휴머노이드의 MoveDirection 대신 `ContextActionService`나 입력 서비스의 벡터값을 직접 바인딩하면 모든 플랫폼에서 동일한 감각을 제공할 수 있습니다.
